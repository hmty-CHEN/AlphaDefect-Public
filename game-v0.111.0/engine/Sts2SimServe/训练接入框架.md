# sts2-sim 接入训练：框架

2026-11-01 起草。用户：“把 sim 用进训练里，写一个框架文档，规划路线，讲怎么用进去，并让引擎可更新，后续消减差异以后要能顺利接入训练进程，最好热更新。只搭框架，不做过多设计。”

本文只定方向、接口和流程，具体设计以后再做。现状见同目录的 方案.md、保真度.md、观测移植清单.md、协议.md。

## 一、为什么要用进训练

sts2-sim 现在的状态：

- 战斗规则：1,146 场对拍战斗里 1,123 场与真实游戏整场一致（99.7%），决策一致 32,708/32,711。
- 观测：移植了格式 19；与真实引擎逐字段对拍，绝大多数字段完全一致，剩余差异记在观测移植清单最后一节。
- 速度：每步约 0.5 毫秒（不含编码），比 C# 无头引擎快 25–40 倍；能复制战斗状态（约 0.09 毫秒）、重抽随机数、按真实帧同步局面。

决策时套一层搜索，在当前模型上没有测出胜负收益（方案.md 的 m3、m6、t1、t2、r1 各轮）。学术上的常见解释是：网络没有和搜索一起训练过，搜索会放大价值头的误差。
所以把 sts2-sim 用进训练，有两层意思：

1. 让训练更快：一部分战斗练习换到 sts2-sim 上跑；
2. 让网络和搜索配套：用搜索的结果当训练目标（专家迭代），之后决策时的搜索才有可能持续有效。

## 二、三种用法（按先后）

| 用法 | 得到什么 | 前提 | 风险 |
|---|---|---|---|
| A. 战斗练习换到 sts2-sim | 同样的机器，Boss 练习、连打练习的样本多出很多倍 | sts2-sim 能按练习规格直接开战（方案.md 最后一节的调研）；练习模式的观测 | 剩余的规则、观测差异让练习数据有轻微偏差 |
| B. 搜索产生训练目标（专家迭代） | Boss 战里拿不准的决策，用搜索给出改进后的策略目标与价值目标 | 用法 A 的练习环境；搜索结果能写进轨迹 | 目标本身有噪声（赢家诅咒）；蒸馏方式要重新定（决策记录 217 的离线蒸馏没有收益） |
| C. 推演结果当价值目标 | 推演打到战斗结束，得到低方差的局面价值 | 同 B | 计算量大，只适合少量关键局面 |

先做 A：它不依赖搜索有没有收益，见效最快；B、C 都建立在 A 的练习环境上。

## 三、怎么接进训练进程

### 3.1 sts2-sim 作为一种采集环境

- 采集端现在的环境是真实引擎（Sts2Headless，经 sts2env 的进程协议）。sts2-sim 服务说的是同一套协议（reset / step，回同格式的观测帧），所以在采集端只是**多一种环境后端**，不改轨迹格式、不改学习端。
- 要补的接口：服务支持 `reset mode=combat`（按练习规格开战，含连打），回帧时带上结束帧、胜负和特权特征，与真实引擎的战斗模式一致。
- 分配：采集端按配置把一部分战斗练习环境指到 sts2-sim，其余照旧用真实引擎。整局对局始终用真实引擎（sts2-sim 只能复制战斗，局外部分没有移植）。

### 3.2 轨迹标明来源

每条轨迹（以及房间记录、练习战结果）都记：

- `engine`：`real` 或 `sim`；
- `sim_build`：sts2-sim 的构建编号（见第四节），真实引擎为空。

学习端据此可以：按来源分别统计；对 sim 轨迹单独加权；某个构建出问题时，丢弃它产出的轨迹。

### 3.3 配置（先只列字段，默认全关）

| 字段 | 含义 | 默认 |
|---|---|---|
| `sim_share` | 战斗练习里用 sts2-sim 的比例 | 0 |
| `sim_build` | 用哪个构建：`current`（跟随发布指针）或具体编号 | `current` |
| `sim_rooms` | 哪些练习换到 sts2-sim（如第三幕 Boss、连打） | 待定 |
| `sim_weight` | sim 轨迹在损失里的权重 | 1.0 |
| `search_targets` | 用法 B：是否让搜索给 sim 练习产生目标 | 关 |

上线任何一项都是训练改动，要用户批准、写决策记录、加看板标线，并按护栏观察。

## 四、引擎可更新：构建、准入、发布、热更新

目标：保真度修复、观测差异修复以后，新的 sts2-sim 能按固定流程进入训练，不停训，出问题能一步回退。

### 4.1 构建编号

一个构建由这几样决定，合起来算一个编号（`sim_build`，例如内容哈希的前 8 位）：

- sts2-sim 上游提交；
- patches/ 下全部补丁的内容；
- Sts2SimServe 的提交；
- sim_tables.json；
- 观测格式版本。

构建产物放在固定位置，比如 `~/sim-builds/<编号>/`，里面有 Sts2SimServe.dll、依赖、sim_tables.json，以及一份 `build.json`（上面几项的明细与准入结果）。构建一旦生成就不再改动。

### 4.2 准入闸门

新构建要先过这几关，任何一项比当前发布的构建差就拒绝：

1. sts2-sim 自带测试全过；
2. 战斗对拍语料：导入成功、整场一致的场数不少于当前构建（`Sts2SimServe check`，保真度.md 的四批语料）；
3. 观测逐字段对拍：完全一致的字段数不少于当前构建（`obscheck`），读档检查全部一致（`OBS_RELOAD=1`）；
4. 冒烟：按练习规格开几场战斗，能打完、没有报错。

以后用一个脚本串起来（暂定 `tools/sim_release.sh`），结果写进 `build.json`。

### 4.3 发布指针与热更新

- 发布 = 改一个指针文件（如 `~/sim-builds/current.json`，写当前构建编号）。回退 = 把指针改回上一个编号。
- 采集端的 sts2-sim 进程在**局与局之间**检查指针：编号变了，就结束旧进程、按新构建拉起新进程，再开下一局。正在打的那一局照旧用旧构建打完，所以不会有一局跨两个构建。
- 这就是进程级的热更新：学习端不停，采集端不重启，只是 sts2-sim 子进程逐个换新。轨迹里的 `sim_build` 会看到新旧交替，持续一两分钟。
- 租用机：构建产物先同步到 A、B 的同一路径，再改各机的指针。指针在各机本地，可以先在一台机器上试。

### 4.4 上线后的护栏

- 同规格的练习战，sim 与真实引擎的胜率、剩余生命、回合数的差别（分布比较），超过阈值就报警；
- 新构建发布后，比较前后一段时间的上述差别，变大就回退指针；
- 护栏触发只暂停（把 `sim_share` 调回 0 或回退指针）并报告，不自动做别的改动。

## 五、路线

| 阶段 | 内容 | 完成的标志 |
|---|---|---|
| 0 | 构建编号、准入脚本、发布指针（不接训练） | 现有版本能按流程生成构建、通过准入、写进指针 |
| 1 | 练习模式：服务的 `reset mode=combat`、连打、练习用的根帧；采集端的 sim 后端（默认关） | 同规格两边开局帧逐字段一致；几十个规格的胜率分布与真实引擎相近 |
| 2 | 小比例上线用法 A（如第三幕 Boss 练习的一部分），护栏盯着；验证热更新与回退 | 训练指标与评测不退步；一次真实的构建更新顺利完成 |
| 3 | 用法 B：sim 练习里在拿不准的决策上跑搜索，把结果写进轨迹当目标；先小比例 A/B | 评测上能看出改进，或者确认无效后撤回 |

每个阶段结束都由用户决定是否进入下一阶段。
