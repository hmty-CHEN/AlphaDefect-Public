# sts2-sim 搜索：静默猎手适配（2026-11-10）

用户：“你看一下那个搜索用的模拟器是不是对标格式23的？如果没有的话，你帮我做一下。”

查的结果：不是。搜索用的移植版编码器（ObsPort）只会出格式 19（故障机器人）和 20（储君），猎人的帧是格式 23（引擎 b298bdf 起；11-10 以前是 21）；对拍工具读到 23 的帧直接报错；策略端的 `SIM_ENGINES` 里也没有猎人，换成猎人直播时 sts2-sim 搜索不会开。照储君适配（储君适配.md）的做法补齐了三样：观测、规则核对、策略端。

结论：

- **规则**：sts2-sim 推演猎人的牌本来就对。300 场里一开始只有 2 场对不上，查下来都是对拍工具挑错了同名牌的副本，不是规则差异；修了工具之后 300 / 300 整场一致，决策 10,319 / 10,319。这次没有给 sts2-sim 打补丁，工作区照旧是 fidelity-01–11、import-0001、obs-0001、regent-01–04。
- **观测**：ObsPort 移植了格式 21 / 23，逐字段对拍除两项早就登记过的例外外全部 100%。
- **搜索那条路**：每步存档、读档、编码，再与真实帧比，300 / 300 场全程一致（第三幕 Boss 28 / 28）。
- **策略端**：`SIM_ENGINES` 加猎人，用新编的 `live/sim_engine_v23`。直播在用的 `sim_engine`（故障机器人）、`sim_engine_v20`（储君）没换。

## 一、对拍语料

真实引擎（当前源码 b298bdf 编的 Sts2Headless，猎人默认出格式 23）用直播准备好的猎人第 19,949 版贪心整局打 16 个种子（SIMSL0000–0015），带特权特征，每场战斗前存游戏自己的整局存档：共 300 场战斗、10,319 个战斗决策，其中第三幕 Boss 28 场。16 局里通关 8 局。语料在热开发目录 `.cache/simcorpus-silent/all.jsonl`。

```bash
.venv/bin/python -I tools/sim_corpus.py --ckpt ~/.local/share/sls2/live/ckpt-silent/v19949-20261110-猎人.pt \
  --dll .cache/eng-now-1110/Sts2Headless.dll --character SILENT --prefix SIMSL --start 0 --seeds 8 --privileged \
  --out .cache/simcorpus-silent --file sl_0.jsonl
```

## 二、规则（Check.cs）

| 阶段 | 整场一致 | 第三幕 Boss |
|---|---|---|
| 当前工作区，不改 | 298 / 300，决策 10,275 / 10,277 | 27 / 28 |
| 对拍工具按副本次序挑同名牌 | 300 / 300，决策 10,319 / 10,319 | 28 / 28 |

那两场（SIMSL0010 第 23 层、SIMSL0002 第 48 层）是同一个原因：手里有几张完全一样的牌（三张防御）时，游戏打的是其中某一张，对拍工具的 `Pick` 总挑第一张能打的。手牌顺序于是和游戏不同，回合末按手牌顺序弃牌，弃牌堆顺序不同，洗牌之后抽到的牌就不同了（SIMSL0010：游戏第 2 回合打的是最右边那张防御，工具打了中间那张；第 3 回合末弃牌“防御、毒雾”变成“毒雾、防御”，第 4 回合抽到的是计划妥当而不是打击）。改成：几张完全等价的副本，按“这张是游戏手牌里同类的第几张”挑 sts2-sim 手牌里同类的第几张。

直播镜像不受这个影响：`tools/sim_pimc.py` 的 `cand_keys` 本来就给相同的候选按出现先后编号对应。

对拍工具另外改了一处：`Frame.cs` 认格式 21、23（布局与 19、20 相同）。

## 三、观测（ObsCheck.cs，obscheck）

ObsPort 照 Sts2Headless 的 V21 / V23 分支移植（新文件 `ObsPort/Silent.cs`，`Observation` 改成分部类；这一帧用哪个格式跟根帧）：

- 格式 21：敌人中毒记录 12–13（下一个敌方回合开头毒实际打掉多少血、毒不毒得死；滑溜、缓冲、硬化外壳）；刀刃陷阱、毒性爆发的候选 4–7；紧勒、群蛇形态的附带伤害算进 4–7，余像的格挡算进候选 8；战斗计数子类型 2（本回合弃牌数、本场抽牌数，读 sts2-sim 的 `PlayerCombatState.CardsDiscardedThisTurn` / `CardsDrawnThisCombat`，铭记死亡、谋杀用的就是它们）。
- 格式 23：候选 10 算上这一步给敌人上的虚弱、减力量，实验体的激怒、感染棱柱的感染，加毒与打伤之后毒得死的敌人（`Fx23`）；回合结束预演判断毒得死改用 PoisonNext；荆棘反伤与凋萎（格式 22 里猎人也用的两项）。重算敌人攻击要按游戏 `Hook.ModifyDamage` 的分段（加法与乘法一段、上限一段），sts2-sim 的钩子只有一次跑完的版本，在编码器里照它的写法拆了一份只读的 `DamageStages`。
- 没移植格式 22 的其余部分（奥斯提、灾厄、铁甲战士的附带效果、战斗计数子类型 3）：猎人用不到，格式 23 也不含。

结果（300 场，11,510 帧，带特权特征比）：

| 字段 | 第一次（照搬） | 修完 |
|---|---|---|
| 出牌候选 10、11（做完这步就结束回合掉多少血） | 95.98% | 100% |
| 药水候选 10、11 | 98.99% | 100% |
| 出牌候选 8、卡牌特征 17（格挡预览） | 99.50%、99.88% | 100% |
| 出牌候选 4、6、7 | 99.91–99.99% | 100% |
| 遗物特征 2（已用完） | 98.83% | 100% |
| 遗物特征 5（激活中） | 99.99% | 100% |
| 选牌说明（记录 12） | 99.50%，另多出 6 条 | 100% |
| 其余全部字段 | 100% | 100% |

修的问题：

1. **数值表的键名**：sts2-sim 的数值表里虚弱、中毒的层数叫 `WeakPower`、`PoisonPower`（游戏 `DynamicVars.Weak` 背后的键名），照搬时写成了 `Weak`、`Poison`，查不到就当 0，候选 10 的虚弱、加毒全没算上。
2. **计算型格挡**（通用垫片 `SimApi.Calculate`，故障机器人、储君也走这里）：表里蜃景这类牌的倍数项叫 `CalculationExtra`，垫片只按 `ExtraBlock` 查，查不到就是 0。改成先查专名、没有再退回 `CalculationExtra`（同游戏 CalculatedBlockVar）。表里所有带 CalculatedBlock 的牌（蜃景、恶魔之盾、准备战斗、模仿、献祭、君王之剑、堆叠）都没有 `ExtraBlock` 这一项。
3. **熔岩石**：sts2-sim 给它加了“已用完”，游戏没有重写 IsUsedUp（触发后只把状态设成失效）。编码器照游戏去掉。游戏与 sts2-sim 重写 IsUsedUp 的遗物名单只差这一个。
4. **石历的激活中**：游戏在第 7 回合的 AfterSideTurnStart 设激活，回合开头先结算的选牌（必备工具的抽一弃一）时还没激活；原来按回合数判断。改读 sts2-sim 同一时机设的 `_shouldTriggerThisTurn`。
5. **佩尔军团的激活中**：战斗开头第一次回合开始之前（悖论之选等开局选牌）游戏还是普通状态，原来只看冷却。
6. **悖论之选的选牌说明**：游戏用 `RelicModel.L10NLookup("CHOICES_PARADOX.selectionScreenPrompt")`，是它自己的提示语；生成提示语表的静态扫描只认 SelectionScreenPrompt 属性，漏了这一处（全量查过，只有它这样写）。

剩下的两项是储君适配时就登记的例外：头部 14（词表外键数，模型不读）98.62%，宠物的招式记录（佩尔军团，sts2-sim 的宠物没有下一招）98.29%。另有 1 场在第一幕 Boss 的“10 亿血”占位敌人处分叉截断（sts2-sim 扣了它的血），储君语料里同样有 3 场，是原来就有的问题。

## 六、策略端与实测

- `python/play_live.py` 的 `SIM_ENGINES` 加 `"SILENT": live/sim_engine_v23`。编译命令同储君，输出目录换成 `sim_engine_v23`；与对拍用的 `.cache/sim-silent` 逐字节相同。换成猎人直播（看板“切到静默猎手”）重开策略端后生效；哨兵 `live/sim_search.on` 照常管开关，默认只搜第三幕两个 Boss。正在跑的储君策略端不受影响。
- 假模组（测试端口、搜索日志写临时目录）打一整局猎人，种子 LIVETEST23，第 19,949 版，第 1–3 幕的 Boss 和精英都搜：通关，895 步；搜索 200 次、改选 20 次（10%），单次中位约 1.0 秒、最长 2.3 秒，没有超时；1 场问号房战斗没有存档、按贪心（已知情形）；没有镜像跟丢。sts2-sim 日志里只有“战斗已结束不能保存”“选牌途中不能保存”两种拒绝，是推演走到终局或选牌时的正常情况，直播储君的日志里同样大量出现。

## 七、搜索评测冒烟

本机跑 8 个种子（SIMSLP0000–0007，分两片），参数同储君冒烟：`--character SILENT --evaluator model --sync --sim-procs 2`，只出第三幕 Boss 题，结果目录 `.cache/pimc-silent-smoke/`。

- 8 个种子都打到第三幕 Boss，共 8 题：贪心 7 题赢、搜索 7 题赢（只有搜索赢 1、只有贪心赢 1，差 0 ± 18.9 个百分点，样本太小，看不出收益）。两边都赢的 6 题里，搜索平均多剩 14.2 个百分点生命（多 5、少 0、相同 1）。
- 搜索臂 929 个决策：搜索 522 次、改选 54 次（10.3%）、退回贪心 4 次（都是“无锚点”）；推演 13,520 个世界，报错 0、还原根局面不一致 0、两个镜像进程之间不一致 0。
- 每次搜索平均 0.95 秒，中位 1.00，p90 1.43，最长 2.78（本机 CPU）。
- 镜像 16 场逐场一致、决策 929 / 929 对上，没有宽松对应、按下标对应，镜像作废 0 场。
- 整帧逐字节一致 634 / 929，每场第一处不同都在头部 2（记录数，宠物佩尔军团的招式记录少一条，同第三节的例外），储君冒烟同样如此。
