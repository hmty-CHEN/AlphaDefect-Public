# 基于 sts2-sim 的战斗搜索：方案与进度

2026-11-01 起。用户：“把我们的搜索实现出来”“以我们的观测为清单，一项一项通过”“局外搜索之后做，先把战斗搞定”。

## 目标

战斗里的 PIMC 改选搜索（项目实测 C# 推演 +6.7 ± 1.7），推演换成 sts2-sim：它是游戏 v0.111.0 的 C# 逐字移植（MIT），
能复制战斗状态（`CombatState.Clone`，约 0.09 毫秒）、每步约 0.19 毫秒，比我们的 C# 无头引擎快 25–40 倍，且不必从战斗开头重放。
模型（策略与价值头）读的是我们的观测格式 19，所以要在 sts2-sim 上产出与真实引擎逐字段一致的观测。

## 已核对（2026-11-01，A）

- sts2-sim 自带测试 4,665 项：通过 4,662、失败 0、跳过 3。
- 速度：随机出牌整局，稳定后每个战斗动作约 0.19 毫秒、复制战斗状态约 0.09 毫秒（单线程，A 同时在跑评测）。
- 同种子对拍（第 134,704 版新随机种子的 30 局，按我们的选择驱动 sts2-sim）：涅奥选项 30/30、第一层地图 25/25、第一场遭遇 25/25 一致；
  第一场战斗能完整重放的 23 场里 22 场逐个决策一致（手牌、双方生命与格挡），WP0022 第 7 个决策前手牌不同，待查。
  另 5 局卡在涅奥奖励的选牌、2 局用了药水，是对拍程序还没覆盖，不算差异。

## 做法

1. **字段清单**（`观测移植清单.md`）：从 `Sts2Headless/Engine/Observation.cs` 的全部写入处静态抽取，只列战斗会输出的部分
   （头部、全局、生物、能力、卡牌与已选的牌、遗物、药水、充能球、招式、选牌说明、战斗计数、出怪池、候选），共 222 处；
   每项记出处行、《观测格式.md》的定义、sts2-sim 的数据来源、状态。
2. **同一局面**：真实引擎在整局的选路决策（下一格是战斗）时导出“移植快照”（sts2-sim 的 `RunTransplantSnapshot`，
   原生游戏 → 模拟器的导入格式：种子、幕、走过的格子、目标格子、玩家牌组与遗物的保存属性、药水、玩家与整局的随机数和几率、本幕遭遇进度、遗物袋），
   然后自己进这场战斗、记下每一帧完整观测与每个动作；sts2-sim 导入快照进同一场战斗，按同样的动作推进。
   随机数状态从游戏原样带过来，两边从开局起就一致。
3. **对拍器**：每个决策点两边各出一帧，按清单逐字段比较（float32），按字段统计一致率、给出第一处不一致的局面。
4. **逐项实现**：按清单在 sts2-sim 上实现观测，一项在对拍语料上全部一致才勾掉；做不到的列为例外并写原因。
5. **搜索服务**（`Sts2SimServe`）：说 Sts2Headless 的协议（reset / step / reseed），另加 save / load（复制战斗状态到槽位、从槽位恢复）。
   reseed 换掉以后要用的全部随机数并重洗抽牌堆（不碰真实随机数）。
6. **PIMC**（Python）：第二、三幕 Boss 战、策略最想选的项概率 < 0.9 时；取前 4 个候选，K 个重抽的世界，每个候选每个世界贪心推演 12 步、价值头估值，
   与贪心项逐世界配对，平均差超过 2 个标准误才改选。验收：sts2-sim 规划、我们的 C# 引擎执行，双 Boss 卷与第三幕快照，对贪心配对。

## 局外搜索（以后）

见后续计划第十节：sts2-sim 只能复制战斗状态，整局状态不能深克隆；局外分支用种子重放或重键随机数模式。

## 进度：第三幕在内的战斗局面对拍（2026-11-01，A）

- 语料：`tools/sim_corpus.py` 用第 138,251 版模型在真实引擎上贪心打 2 局（A 的独立副本，Sts2Headless 加了只读的 `save` 操作），
  每场战斗前存游戏自己的整局存档与目标格子，记下全部原始观测帧与动作：40 场（普通 21、精英 11、Boss 8，含第三幕两个 Boss 各 2 场）。
- 对拍（`Sts2SimServe check`）：存档 → `NativeSave.ToSnapshot` → `RunTransplantImporter.Import` → `RunDriver.RunOneCombatFromTransplantAsync`，按语料动作重放，
  每个决策前比玩家生命、格挡、能量、手牌，敌人生命与格挡。
- 结果：40 场全部导入；整场一致 36/40，决策一致 1,186/1,190（99.7%）；**Boss 8/8 整场一致（第三幕 4 场全对）**。
  - 转换器要点：遗物袋稀有度写成枚举名（Uncommon），卡牌与遗物的保存属性整个放在 "props" 键下（遗物另带 floor_added_to_deck），
    整局附加字段 `test_subject_kills` sts2-sim 不认，去掉（那场仍整场一致），玩家的 damage_dealt、debuffs_applied 放进 Player.*。
  - 对拍程序按卡牌 ID、升级、附魔、当前费用找对应的那张牌（原来只按 ID 和升级，打错副本造成过 6 处假差异）。
  - 剩下 4 处都在 SIMC0000：抽到的同名牌升级状态不同（冷静头脑、光束、编译驱动、防御）。导入后牌组顺序与存档一致，差异出在战斗里；
    下次采语料开特权特征（抽牌堆真实顺序），比开战时两边的抽牌堆顺序。

## 以后：用 sts2-sim 跑战斗练习，给训练提速（2026-11-01 记，用户：先记下，之后再做）

想法：训练里的战斗模式练习（Boss 练习、第三幕连打）挪一部分到 sts2-sim 上跑。sts2-sim 每步比 C# 无头引擎快 25–40 倍，同样的机器能多产出很多倍练习轨迹。
这条不依赖搜索有没有收益；上线要用户批准，并且按比例混入、A/B 对比、写决策记录。

已经摸清的（没写代码）：
- **练习规格**：sts2rl/curriculum.py 生成，actor.py 用 {"op":"reset","mode":"combat","spec":…,"privileged":true} 发给真实引擎。
  字段有 character、ascension、seed、act、encounter（具体 ID）、room、player_snapshot，连打另有 next_encounter、prev_encounter。
  player_snapshot 是游戏的 SerializablePlayer JSON（Snapshot.Player），与整局存档里 players[0] 同一格式。
- **真实引擎的做法**（Sts2Headless/Engine/CombatSpec.cs 的 CombatSetup.Start）：
  1. HeadlessRun.CreateRun(角色, 进阶, 种子)；
  2. CurrentActIndex = act；
  3. Snapshot.Restore 换上快照里的玩家，但随机数、几率、遗物袋保留新开那一局的；
  4. EnterRoomDebug 进遭遇。
  连打在打赢后带着当时的血量、药水、牌组接着打下一场（RunSession.StartCombat）。
- **sts2-sim 这边可以这样做**：
  - 有现成的注入入口 RunDriver.RunOneInjectedCombatAsync(房间类型, 遭遇)：两个房间之间直接开战，不走地图；
  - 导入器支持注入式快照（RunTransplantSnapshot.IsInjected = true，不要目标格子）；
  - 快照要全套随机数流、几率、遗物袋。做法：用种子 new RunState(seed, ActDefinition.GetRandomList(seed), 进阶)，加 Player.CreateForNewRun；
    取 run.Rng.ToSerializable()、run.Odds.ToSerializable()、player.PlayerRng / Odds / RelicGrabBag 的导出；
    牌组、遗物、药水、生命、金币、删牌次数从 player_snapshot 转（复用 NativeSave 的玩家部分：Props、Bag、Rngs、Pascal 要改成 internal）；
    幕名用幕的类名。共享遗物袋在新建的局里可能还没初始化，先用空袋或玩家袋试。
  - 如果 sts2-sim 的种子派生和游戏一致，同规格两边抽牌可能逐张相同，就能逐步对拍；否则只能比开局第一帧、按统计比输赢分布。
- **观测**：练习没有根帧，要另造 RootContext。头部 16、17、23、24、25 按 Sts2Headless 的 CombatOnly 分支，用 BossPrev / BossNext / Stage；
  不出出怪池；头部 18–22 为 0；全局几率（特征 16–19）是新开一局的初值，可以从一帧真实练习帧里取常数；头部 28、29 取自快照里的删牌次数与对应价格。
  训练要特权特征（抽牌堆顺序、怪物下一次抽签），移植版已经支持（Observation.Privileged）。
- **还要做**：
  - Session.StartPractice 与服务的 reset mode=combat；
  - 连打（第一场打赢后 Exit 房间、再注入下一场）；
  - 练习用的 RootContext；
  - 一次同规格对拍（开局帧逐字段比），一次几十个规格的输赢分布对比；
  - 采集端按比例把一部分练习环境指到 sts2-sim 服务。
