# 观测与候选格式（格式版本 19；储君为格式 20，见四之二；静默猎手原为格式 21，见四之三；铁甲战士、亡灵契约师为格式 22，见四之四；静默猎手 2026-11-10 起为格式 23，见四之五；Fool（游戏 v0.113.0）原为格式 24，见四之六；2026-11-13 起 Fool 为格式 25，并对格式 19–23 做了 v0.113.0 修正，见四之七；同日下午起 Fool 为格式 26，候选特征加到 14 项，见四之九；2026-11-17 起铁甲战士为格式 28（格式 27 加格式 22），见四之十三；2026-11-20 起铁甲战士为格式 29（六个角色统一，含全角色观测缺口调研的修正），见四之十四）

引擎与训练端之间的数据格式。C# 实现在 `engine/Sts2Headless/Engine/Observation.cs` 与 `Engine/Obs/` 下的分部类文件（按区域与角色拆分，见 `引擎模块与游戏更新适配.md`），Python 解析在 `python/sts2env/protocol.py`。改动布局时两边同时改，并把版本号加 1。

## 一、通信

- 每个引擎进程运行一局（游戏逻辑是单例），并行靠多进程。启动命令：`dotnet Sts2Headless.dll serve`。
- 请求：一行 JSON，写到进程的标准输入。
- 响应：`int32 字节数` + 内容，从标准输出读取。内容开头的 int32 为 −1 表示出错，后面是 UTF-8 错误信息，进程仍可继续使用。

| 请求 | 说明 |
|---|---|
| `{"op":"reset","mode":"run","character":"IRONCLAD","ascension":10,"seed":"S1"}` | 整局模式，从 Neow 开始 |
| `{"op":"reset","mode":"combat","spec":{...}}` | 战斗模式，按 CombatSpec 直接开一场战斗，战斗结束即结束 |
| `{"op":"step","action":3}` | 选第 3 个候选 |
| `{"op":"vocab"}` | 返回词表（每行一个键，行号即 ID） |
| `{"op":"close"}` | 退出 |

reset 加 `"labels":true` 时，每个候选附带文字说明，供调试用。

reset 加 `"privileged":true` 时才输出特权特征（版本 11 起；见第二节“特权特征”），不加时所有记录的特权特征一律为 0。只有训练采集请求它；评测、实机、搜索、各种工具都不请求，决策时拿不到任何随机数结果。整局 reset 加 `"auto_gold":false` 时金币奖励不自动领，作为奖励界面的“领奖励”候选交给策略（决策记录 160）。

CombatSpec 字段（均可省略）：`character`、`ascension`（默认 10）、`seed`、`act`（0–2）、`encounter`（`weak` / `regular` / `elite` / `boss`，或具体遭遇 ID）、`deck`（`[{"id":"STRIKE_IRONCLAD","upgrades":1}, ...]`，省略为初始牌组）、`relics`、`potions`（ID 列表，在初始配置之外追加）、`hp`、`max_hp`、`gold`。

## 四之二、格式 20（储君，2026-11-06）

## 五、词表与内容目录

- 词表：`engine/catalog/vocab.txt`，行号即 ID；0 填充，1 未知。**只追加，不重排**。游戏更新后运行 `Sts2Headless.dll catalog <版本>`，新内容追加到末尾，旧 ID 不变。
- 键的形式：模型为“类别.条目”（如 `CARD.STRIKE_IRONCLAD`、`POWER.VULNERABLE_POWER`）；其他为“前缀:名字”（`EVENTOPT:`、`REST:`、`ALT:`、`REWARD:`、`MAPNODE:`、`INTENT:`、`SHOP:`）。
- 内容目录：`engine/catalog/<版本>/catalog.json`，记录每个实体的静态属性（卡牌的类型、稀有度、目标、费用、关键字、数值；遗物、药水的稀有度；能力的增减益；怪物的血量范围等），以及效果签名：
  - `hook:X`：重写的游戏钩子；
  - `cmd:X.Y`：调用的命令；
  - `ref:CATEGORY.ENTRY`：引用的其他模型（如施加的能力）。

  这些都来自代码分析，不依赖文本，新内容上线即可使用。
