# 卡牌游戏 AI 的状态/动作表示与同类项目实证（服务于 STS2 第三幕双 Boss 专项模型）

> 检索日期：2026-11-06。来源多为 GitHub README 与论文原文；README 中的胜率均为作者自报，口径（种子数、进阶等级、是否实机）各不相同，不能横向直接比较。凡未能从原文核实的内容放在「Gaps」。

## 问题一：《杀戮尖塔》1/2 的社区与学术 bot：战斗用搜索还是 RL？什么进阶、什么胜率？什么有效、什么失败？

### Takeaway
在 STS1 里，能稳定打出胜率的 bot，战斗**无一例外靠模拟器搜索**（MCTS、按回合枚举出牌顺序、或 sims 很少但复用子树的搜索）；学到的网络只在局外决策（路线、选牌、商店）上明显有效。把战斗蒸馏进网络的尝试，有好几份公开的失败记录，失败的共同原因是**老师在搜索时看到了真实的未来抽牌顺序**。STS2 方面，Combat Solver 是基于 beam search 的整场跨回合求解器；STS2 上的 RL 项目目前只有第一幕、低进阶的结果。

### Cited Findings

**STS1：sts_lightspeed 与基于它的项目**
- sts_lightspeed（gamerpuppy）是用 C++17 重写的 STS 模拟器，自称「100% RNG accurate」，16 线程 5 秒可跑 100 万次随机 playout。已实现全部敌人、全部遗物、全部 Ironclad 卡和无色卡。README 写明当前的树搜索「best result, knowing the state of the game's rng」，即**已知 RNG 状态**；「不给 RNG 状态的树搜索」仍是计划中的功能 — [gamerpuppy/sts_lightspeed](https://github.com/gamerpuppy/sts_lightspeed)
- **sts-rl-agent**（Jialeiv 原作，destire-mio 为 fork；页面无日期）：局外由约 100k 参数的 MLP（隐藏层 [128,128]）打分，用 REINFORCE 从零训练，输入为 412 维观测与每个合法候选的 368 维描述向量拼接后打分取 argmax（即「候选动作打分」式）；战斗交给 sts_lightspeed 自带的 MCTS。50 个留出种子、A0 Ironclad 的结果：启发式局外 + MCTS@2000 平均 22.8 层、胜率 2%；启发式 + MCTS@50000 为 31.2 层、6%；学到的局外 + MCTS@2000 为 38.5 层、4%；学到的局外 + MCTS@50000 为 42.5 层、14%。进阶阶梯（sim2000）：A0 38.5 层、A5 33.4、A10 30.1、A20 25.7（A20 胜率 0%）。训练在 12 核笔记本上约 10 分钟 — [destire-mio/sts-rl-agent](https://github.com/destire-mio/sts-rl-agent)
- 同一项目列出的**六个「把战斗蒸馏进网络」的失败**：(1) 行为克隆 MCTS：模仿准确率 0.59，只能打到约 12 层；训练准确率上限约 0.44。作者的解释是老师用了真实的未来抽牌顺序，单帧策略看不到这些信息。(2) DAgger 无改进，标签本身学不会。(3) REINFORCE 微调：约 12 层。(4) attention/token 打分器：约 14 层。(5) 价值网络 + 1 步前瞻：约 8 层，比不前瞻还差。(6) 策略/价值引导的 PUCT：随模拟次数增加而变好，但同预算下输给盲目 rollout（100 次模拟时盲目 self-play 26.7 层，引导版 33；页面原文如此，与「输给」的表述看似矛盾，见 Gaps），作者认为原因是「半训练好的网络会误导搜索树」。作者的总结：判断类决策（路线、商店、构筑）容易压缩进小网络，规划类决策（战斗出牌顺序）难以压缩，可能需要 AlphaZero 式的自博弈循环 — [destire-mio/sts-rl-agent](https://github.com/destire-mio/sts-rl-agent)
- **sts-ironclad-agent**（destire-mio，延续上一项目；报告文件名日期为 2026-10-01）：A20 Ironclad、三钥匙 + 心脏。战斗是模拟器搜索（`sims32`，Boss 战有额外预算，复用子树）；局外由一个冻结网络完成，从 P300 老师蒸馏而来。结果：模拟器中老师 2,000 局心脏胜率 50.1%，新种子块 1,000 局 49.5%；学生 1,000 局 50.2%；**原版游戏 501 局 50.1%（95% CI 45.7–54.5）**。在模拟器 3,000 局中，各阶段死亡率最高的是心脏（21.3%）。页面未说明搜索如何处理抽牌顺序和敌人行动（是否作弊）。模拟器与实机仍未做到逐步一致（标注 INCOMPLETE）— [destire-mio/sts-ironclad-agent](https://github.com/destire-mio/sts-ironclad-agent)
- **AscensionAI**（Ironclad，sts_lightspeed；2026 年 6 月）：在实机上做 PPO（先 BC 热启动），约 21,700 局 0 胜，平均层数停在约 14.7；峰值评估 200 局为 14.66 层、Boss 胜率 38.1%。实机只有约 90 局/小时，改用 headless 模拟器后约 17k 局/小时。**把战斗换成「1 步重放搜索」后，Boss 战胜率从学到的前馈策略的 44% 升到 75–88%**，平均层数从 14.7 升到 26.4。mainline_v3（2026-06-17）在 150 个固定种子上平均 26.1 层、9 胜（6.0%）。作者的结论：所有方案的共同瓶颈是战斗执行，而不是奖励设计、网络容量或构筑 — [AscensionAI](https://justinochan.github.io/AscensionAI/)
- **AttemorySystem/spire-agent**：战斗由 MCTS（基于 sts_lightspeed）完成，每步返回一个根动作。药水先对搜索隐藏，只有「不用药水的搜索预测掉血过多」时才放开。`threads` 同时控制并行 worker 数和「RNG-world coverage」，暗示使用多个随机世界（未详述）。README 称 Ironclad 和 Defect 都有多次 A20H 胜利，但没有给出总胜场；最近 12 局 Ironclad 平均 38.6 层。作者认为 MCTS 延迟是最大瓶颈，并称「让 LLM 控制一切」的方案在 A0 都会失败 — [AttemorySystem/spire-agent](https://github.com/AttemorySystem/spire-agent)

**STS1：基于 CommunicationMod 的规则/搜索 bot**
- **bottled_ai**：不用 ML。战斗用「图遍历 + 自建模拟」估计本手牌每种打法的结果，按约 40 个数值加权的评估选最优，再按该顺序出牌，即**按回合整体规划**；只使用玩家可见的信息，不看隐藏的 roll 和后续抽牌。README 中最好的是一套 Watcher 策略，胜率 52%（README 未写进阶等级）— [xaved88/bottled_ai](https://github.com/xaved88/bottled_ai/)
- 在 SpireBench（A20 Ironclad、10 个种子）的测试中，BottledAI（符号版）平均通关 0.20 幕、平均 11.3 层；同一表格中，所有人类玩家平均 0.73 幕，1000 小时以上玩家 0.92 幕，四位专家主播 2.52–3.06 幕 — [SpireBench, arXiv 2610.12596（2026-10）](https://arxiv.org/html/2610.12596v1)
- 第三方 bot 开发者的博客给出过 bottled_ai「26%」和「A20 上公布过 40%」两个不同说法，口径不明 — [DEV Community: Part 7 Diminishing Returns](https://dev.to/doronsinger/part-7-diminishing-returns-38me)（仅见搜索摘要，未全文核实）

**STS1：LLM 基准（作参照）**
- SpireBench：前沿 LLM 在 A20 Ironclad 上平均通关 1.1–1.6 幕，只有一个模型杀过一次心脏。强模型在第一幕普通战斗平均每场掉血 8.2，弱档 14.0；强模型漏算斩杀更少，对下一回合血量的预测较准，但对能否撑过一整幕的判断校准很差 — [SpireBench](https://arxiv.org/html/2610.12596v1)

**STS2**
- **Combat Solver**（原作 Torch1230，有大量 fork）：单人战斗路线求解 mod，可只给建议、执行当前回合或接管整场战斗。搜索为**整场跨回合**，预测未来的抽牌、洗牌、敌人行动和资源，不设固定的回合或洗牌上限，靠循环检测、状态合并和预算限制收敛。算法为受时间、节点数和内存约束的 **Beam Search**，README 明说不承诺全局最优。路线按「整场战略掉血 + 可选药水成本」比较，平局时依次比较成长、结束回合时机、消耗数。预设：低 60 s/60,000 节点，中（默认）120 s/120,000，高 180 s/250,000，极高 300 s/500,000。并行支持单线程或 2–16 线程（默认 4 线程），超过物理核数收益很小。默认开启 NoGC，申请 16 GB 内存区。当前版本 0.48.0，支持 STS2 0.111.0，需要 RitsuLib ≥ 0.6.0。模拟核心改自 hotwords123 的 Random Foreseer（MIT）。README 称搜索「不会修改游戏 RNG」，模拟分支会推进牌堆、RNG、怪物 AI；战前预测 API 用采样种子替换怪物组合、开局洗牌和敌人行动；实际局面偏离预测时重新搜索。README 没有胜率数据 — [Torch1230/CombatSolver](https://github.com/Torch1230/CombatSolver)
  - 数据冲突：搜索引擎摘要称 Torch1230 版为 0.36.4、预设为「低 60 s/12,000 节点 … 极高 300 s/100,000 节点」，而实际抓取的 README 是 0.48.0 和上面的 60k–500k 预设。以抓取到的为准，摘要可能来自旧版本 — [CombatSolver 搜索摘要/fork 列表](https://github.com/llzcx/CombatSolver)
- **sts2-rl-agent**（zhiyue）：Python 战斗模拟器（577 张卡、121 个怪物）+ MaskablePPO（sb3-contrib）+ C# 桥接 mod。README 写观测为 **217 维** float32 向量（玩家状态、手牌、牌堆摘要、敌人状态；每个敌人最多 3 个意图槽，每槽 8 个特征）；战斗动作为 Discrete(115)（结束回合、卡、目标、药水），整局 Discrete(157)，带合法动作 mask。默认参数 lr 3e-4、batch 256、每个环境 2048 步 rollout、4 个并行环境、500k 步。**Act 1 Ironclad 战斗胜率约 92%**，没有其他幕、角色或进阶的数据。约 1,200 场战斗/秒 — [zhiyue/sts2-rl-agent](https://github.com/zhiyue/sts2-rl-agent)。另一处搜索摘要称该观测为 131 维，与 README 不一致，以 README 为准
- **STS2FableBot**：确定性的搜索式决策引擎（通过 STS2MCP 的 fork 运行），A0 343 局胜率 20.7%，A1 175 局 19.4% — [slaythespire.dev 项目索引](https://slaythespire.dev/projects/)
- **AgenticSTS**（LLM）：A0 下不用学到的技能 3/10 胜，用了 6/10 — [slaythespire.dev 项目索引](https://slaythespire.dev/projects/)

### Inferences
- 对本项目最直接的警示：**用 Combat Solver 这种「看得见真实 RNG」的求解器当老师做行为克隆，大概率重演 sts-rl-agent 的失败**（准确率上限 0.44–0.59，因为最优标签依赖策略看不到的抽牌顺序）。Combat Solver README 说模拟分支推进 RNG、预测未来抽牌和洗牌，所以它的实况搜索很可能等价于「已知未来」（这是推断，README 没有明确写「determinize」或「clairvoyant」）。更稳妥的用法是：把它当作上界或评估基线；或在多个重采样世界上分别求解，聚合成可学的标签（PIMC 式）；或只给 critic 用（见问题四）。
- 所有公开的 STS1 强 bot（50% A20 心脏、A20H 胜利）都在推理时用搜索。专项模型如果只用前向策略，大概率比不过「策略 + 少量搜索」。本项目的模拟器能从快照启动、并行快速运行，具备在推理时做浅搜索的条件。
- sts-rl-agent 的第 6 条失败（半训练网络误导 PUCT）说明：如果打算做「网络引导搜索」，网络要先达到足够好的水平，或者搜索要保留随机 rollout 作对照。
- sts-ironclad-agent 中心脏死亡率 21.3%、远高于其他阶段，说明在强 bot 里少数几场 Boss 战占了大部分失败。这和本项目单独训练第三幕双 Boss 专项模型的动机一致。

## 问题二：成功的卡牌游戏 agent 如何表示状态与动作、如何处理可变动作集？

### Takeaway
主流做法收敛到同一个模式：**牌按实体嵌入，按区域（手牌/牌库/墓地/场上）池化，加全局标量；动作每步只选一个原子动作（选择对象，或「类型→目标」两步自回归），用 mask 屏蔽非法动作，通过「动作嵌入与状态嵌入做内积/打分」来处理可变动作集**；「结束回合」被当作一张普通的「牌」来选。本项目现有的 token 集合 + 指针式候选打分头，和 ByteDance Hearthstone、MageZero、sts-rl-agent 的设计基本同构。

### Cited Findings

**Hearthstone（ByteDance，Xiao 等，arXiv 2303.05197，2023-03）**
- 战斗阶段的观测包括：决策类型、己方手牌、**己方牌库（剩余牌）**、己方/对方场上随从及其标量特征、己方/对方墓地，以及双方玩家特征（手牌数、随从数、法力、武器）。牌共享一个 card embedding。网络结构图显示，牌库和墓地经过 cards embed 后做 **mean 池化**（与顺序无关）；手牌和场上用 fc×2 处理 — [arXiv 2303.05197 Tab.V / Fig.2](https://arxiv.org/pdf/2303.05197)
- 动作：每步是**一个类别分布**。打一张牌拆成 (type, target) 两步：type ∈ {手牌, 己方场上, 对方场上, 英雄技能, 结束回合}，target ∈ {己方英雄, 对方英雄, 己方随从, 对方随从}。论文称「通过这种自回归动作分解，每个时间步的动作数最多几十个」，并用 0/1 mask 把不可用动作的概率置零。论文原文：「We regard end turn as a card」。BT 动作头是「action embed」与 LSTM 输出的 **inner product**，即指针式打分 — [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)
- 训练：V-Trace + UPGO，后改为 PPO 式裁剪目标（ε=0.2），外层为 OSFP（optimistic smooth fictitious play）；discount 1.0、LSTM 256、lr 7e-5、batch 1e4×8 GPU、sample reuse 2。最佳非作弊版本 b4 用了 **24 张 V100 + 5,856 个 CPU 核**；对比实验各训练 2 天 — [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)
- 结果：对 COG2022 LoCM 双冠方法（基线）胜率 73.6%，作弊版（可看对手牌库前 n 张）80.2%。对中国区前 10 的主播：b4-23day 两次 Bo5 均 3:0，c5-16day 为 3:1、3:2。逐项改进：把 Actor 减半（使数据生产/消费速度比 c≈1，降低 off-policy 程度）+10.0%；改 V-Trace 裁剪 + PPO 目标 +15.1%；**按英雄拆成独立模型** +6.5%；作弊 +5.5%。论文还发现在网络容量受限时，把 batch、GPU、CPU 加倍或加到三倍都没有提升 — [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)

**Legends of Code and Magic（LoCM）/ ByteRL**
- LoCM 战斗：每位玩家每步拿到 244 维观测；每回合可执行多个动作，最后用 pass 结束；动作编号 0–144。奖励只在终局给出（±1）— [Learning to Beat ByteRL, arXiv 2404.16689（2024-04）](https://arxiv.org/pdf/2404.16689)
- ByteRL（2022 年 LoCM 比赛冠军）：选牌和战斗端到端训练，不用搜索。战斗阶段把手牌、牌库、场上卡等用一维卷积嵌入，拼接后经过 3 层 fc，再接一层贯穿整场战斗的 LSTM，最后经动作 mask 输出 — [arXiv 2404.16689](https://arxiv.org/pdf/2404.16689)
- 对 ByteRL 做行为克隆：去掉 pass 动作（约占 25% 数据）使对 ByteRL 胜率提高约 7%；最好的 BC 网络对 ByteRL 42.4%。再用 RL 微调：固定卡组池为 32/64/128/256/512/1024 时，BC 预训练版胜率分别为 0.904/0.822/0.803/0.801/0.734/0.542，不预训练为 0.812/0.780/0.812/0.720/0.533/0.418，**池越大，BC 预训练的优势越明显** — [arXiv 2404.16689](https://arxiv.org/pdf/2404.16689)

**Magic: The Gathering**
- MageZero（XMage）：状态是**带类型的实体图**（ROOT/PLAYER/ZONE/STACK_OBJECT/PERMANENT/CARD/ABILITY/LEAF 节点，以及所有权、目标、附着等边）。叶节点数值分桶（−5 到 20 取精确值，之后按区间到 61+）。词表用哈希按需追加，新卡不需要重训。**没有固定动作槽**，动作就是它所作用的节点，网络给节点打分：priority 头给 ABILITY 节点打分（pass 是玩家身上的一个 ability），target 头给卡/永久物/栈对象/玩家打分，choose-use 头从 CLS 读出是/否，另有 tanh 价值头。策略用对 MCTS 访问计数的 KL 散度训练，**不使用合法性 mask**，非法节点会被推向 0。单层 Transformer encoder。PUCT（c=1.0），不加 Dirichlet 噪声，作者发现加深搜索比加噪声更能稳定训练。约 800 局/小时（16 线程、300 sims）。UWTempo 对 minimax：minimax 版 16%，RL 版 66%；对五个 minimax bot 平均 47.9%（作者估计人类约 61%）— [WillWroble/MageZero](https://github.com/WillWroble/MageZero)
- jackmaiorino/mage：Transformer 策略/价值网络对编码后的状态打分合法动作，PPO 自博弈 + population-based training — [jackmaiorino/mage](https://github.com/jackmaiorino/mage)（仅见 README 摘要）
- 早期工作：Cowling 等（2012）在 MTG 上做 ensemble determinization MCTS — 引自 [A Taxonomy of CCGs, arXiv 2410.06299](https://arxiv.org/html/2410.06299v1)

**Dominion（牌组构筑）**
- Gerigk & Engels（AIIDE 2023）：**基于多重集（multiset）的游戏表示** + Geometric Deep Learning，Soft Actor-Critic 改为适配可变大小的动作集合。作者称这是第一个不依赖启发式、能做全部决策的学习型 Dominion agent，超过此前所有学习型方法，只在部分配置下输给搜索方法 — [AIIDE 2023 论文页](https://ojs.aaai.org/index.php/AIIDE/article/view/27518)（全文 PDF 被反爬拦截，细节未核实）

**斗地主（大且可变的动作空间，作类比）**
- DouZero：在蒙特卡洛方法基础上加入深度网络、「action encoding」和并行 actor，以应对「每回合合法动作变化很大」的海量动作集。在 Botzone 344 个 AI 中排名第一；4 GPU 单机训练数天 — [DouZero, arXiv 2106.06135](https://arxiv.org/abs/2106.06135)

**Hearthstone 搜索类**
- Hearthstone AI 竞赛（Sabberstone，部分可观测）2020：预组卡组赛道前三均为 Dynamic Lookahead（DL）类，胜率 72.34% / 70.91% / 68.71%；自组卡组赛道第一 DrunkenAggroWarriorAgent（DL）65.47%。最常见的 agent 类型是 MCTS 等模拟搜索和 DL 变体（2019 年的冠军）— [2020 竞赛结果幻灯片](https://hearthstoneai.github.io/files/slides/2020-Results-Hearthstone-AI-Competition.pdf)
- SabberStone 自带「回合内」博弈树搜索，枚举一回合内可能的动作序列，用户提供启发式打分函数评估局面；这一领域的搜索普遍要配合状态评估，因为完整 rollout 噪声太大 — [The Many AI Challenges of Hearthstone, arXiv 1907.06562](https://arxiv.org/pdf/1907.06562)（经搜索摘要转述）
- Zhang & Buro（2017）把结果相近的随机事件分桶，并用高层策略网络引导 MCTS rollout — [cig17-hsai.pdf](https://skatgame.net/mburo/ps/cig17-hsai.pdf)（仅见摘要）

### Inferences
- 本项目的「token 集合 + 指针式候选打分 + 结束回合也是一个候选」已经是业界主流形态，没有证据表明需要改成固定槽位的离散动作（sts2-rl-agent 的 Discrete(115) 是更朴素的做法，只在第一幕验证过）。
- ByteDance 的「按英雄拆成独立模型 +6.5%，而单纯加算力无效」，是对「为第三幕双 Boss 单独训练专项模型」最接近的外部证据：容量受限时，专精比扩规模更有效（推断：前提是专项数据足够多）。
- LoCM 的 BC→RL 结果说明，用强策略的数据做 BC 预训练能显著加速 RL，而且任务分布越宽，收益越大。但这要求老师和学生的信息对等（LoCM 中 ByteRL 也看不到隐藏信息），与问题一中「clairvoyant 老师」的情况不同。
- pass/结束回合在 BC 数据里占比很高，去掉后胜率反而上升约 7%。如果本项目用求解器轨迹做 BC，需要注意「结束回合」样本的权重或单独处理。

### Gaps
- Gwent、Legends of Runeterra、Monster Train：没有找到任何公开的 RL 或搜索 agent 论文或项目（检索结果为空或无关）。
- DouZero 中「把动作编码作为网络输入」的具体维度和格式，只从摘要确认了「action encoding」，未读到正文。
- Dominion 论文的多重集编码细节和数值结果未能读到全文。
- Hearthstone 竞赛中 Dynamic Lookahead 的具体算法（深度、剪枝）没有找到原始描述。

## 问题三：整个回合作为宏动作，还是逐步出牌？

### Takeaway
**没有找到卡牌游戏里「整回合宏动作 vs 逐步原子动作」的直接对照实验。** 现有证据分成两类：**搜索类** bot 普遍以「回合」为规划单元（枚举出牌顺序、评估回合末局面），例如 Hearthstone 竞赛中的 Dynamic Lookahead、SabberStone 的回合内搜索、bottled_ai；**学习类**最强结果（ByteDance Hearthstone 击败前 10 主播、ByteRL、MageZero）全部采用逐步原子动作 + mask。逐步决策的好处是每步动作空间只有几十个，并且能在出牌之间看到新信息（抽到的牌、随机生成的牌）。

### Cited Findings
- ByteDance Hearthstone：逐步、每步一个类别分布、(type, target) 两步自回归，每步「最多几十个」动作；不用前瞻搜索即达到人类顶尖水平 — [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)
- LoCM：每回合多个动作 + pass，每步一个动作；ByteRL 不用搜索，是当前最强 — [arXiv 2404.16689](https://arxiv.org/pdf/2404.16689)
- bottled_ai：在回合层面枚举本手牌的所有打法，模拟后用约 40 个数值的评估选最优，再按顺序执行 — [bottled_ai](https://github.com/xaved88/bottled_ai/)
- SabberStone 提供回合内动作序列搜索 + 启发式评估；Hearthstone 竞赛的冠军多为 Dynamic Lookahead/MCTS — [arXiv 1907.06562](https://arxiv.org/pdf/1907.06562)；[2020 竞赛幻灯片](https://hearthstoneai.github.io/files/slides/2020-Results-Hearthstone-AI-Competition.pdf)
- NTNU 2016 硕士论文为 MCTS Hearthstone agent 引入「action chains」来处理一回合内的多个动作 — [NTNU Open](https://ntnuopen.ntnu.no/ntnu-xmlui/handle/11250/2420367)（仅见摘要）
- 卡牌游戏中最接近的比较：The Lord of the Rings 卡牌游戏的两阶段 RL 论文讨论了「宏动作（抽象）」与「直接选牌」两种形式，指出宏动作让决策空间固定，但牺牲了选择自由；RL agent 在 10,000 局随机对局中总胜率 78.5% — [Godlewski & Sawicki, arXiv 2311.17305（2023-11）](https://arxiv.org/abs/2311.17305)（摘要层面，未见两种形式的数值对比）
- 通用 RL：宏动作在 Atari 上显著加快学习（2016），但宏动作通常被当作独立的原子动作，会让搜索空间严格变大；减少每局决策数与增大动作空间之间存在取舍 — [Deep RL with Macro-Actions, arXiv 1606.04615](https://arxiv.org/pdf/1606.04615)（经搜索摘要转述）
- sts-rl-agent 的 MCTS 与 spire-agent 的 MCTS 都是每次返回一个根动作，即逐步决策 — [sts-rl-agent](https://github.com/destire-mio/sts-rl-agent)；[spire-agent](https://github.com/AttemorySystem/spire-agent)
- SpireBench 的 LLM 可以一次返回整回合的动作序列，按顺序执行，直到某个动作失败为止 — [SpireBench](https://arxiv.org/html/2610.12596v1)

### Inferences
- STS 的一个回合内常有新信息出现（抽牌、随机生成卡、Defect 的充能球随机目标等），整回合宏动作会丢失这些信息，或者需要先对它们做确定化。逐步原子动作 + 指针头仍是 PPO 策略的合理默认。
- 宏动作的价值更可能体现在**搜索/评估端**：用网络的价值头评估「回合末」状态，对本回合出牌序列做浅搜索（bottled_ai 和 Dynamic Lookahead 的模式），比让策略网络直接输出整回合序列更符合现有证据。
- 如果要尝试，比较可行的对照是在同一个专项任务上比较「逐步 PPO」和「逐步 PPO + 回合内序列搜索（价值头评估回合末）」，而不是把动作空间改成整回合。

### Gaps
- 未找到任何在卡牌/牌组构筑游戏里，用相同算力对比「整回合宏动作策略」与「逐步策略」的实验数字。

## 问题四：显式的信念特征（剩余牌堆构成、抽到某张牌的概率、敌人招式概率）有没有帮助？

### Takeaway
在卡牌游戏里，**把「可推断的公开信息」显式放进观测是标准做法**：ByteDance Hearthstone 和 ByteRL 都把己方牌库（剩余牌）编码进观测。至于额外的「隐藏信息」，正面证据有两类：作弊式观测（看对手牌库）带来 +5.5% 胜率；只把完美信息给 critic 或 oracle 的训练方法（PerfectDou 的 PTIE、Suphx 的 oracle guiding）显著加快学习。反面证据同样明确：**让只看部分信息的学生直接模仿完美信息老师，效果不好**（Suphx 明说简单蒸馏不行，sts-rl-agent 的 BC 上限 0.44–0.59）。没有找到「概率特征（如抽到 X 的概率）」本身的消融实验。

### Cited Findings
- ByteDance Hearthstone 的观测包含「my deck: cards in my deck」，即剩余牌库构成；牌库经 card embedding 后做 mean 池化 — [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)
- ByteRL 的战斗观测包含「a player's deck」 — [arXiv 2404.16689](https://arxiv.org/pdf/2404.16689)
- 「作弊」实验：在选牌和战斗观测中加入对手牌库的前 n 张（对手手牌仍不可见），用非对称训练（目标策略看到的 n1 ≥ 对手看到的 n2）避免训练与评估不一致，**比 b4 提升 5.5% 胜率** — [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)
- PerfectDou（NeurIPS 2022）：Perfect-Training-Imperfect-Execution，**critic 接收完美信息特征，actor 只接收不完美信息**，PPO + GAE。早期版本训练 1e9 步就能战胜训练 1e10 步的 DouZero（WP 0.732，ADP 1.270）— [PerfectDou, arXiv 2203.16406](https://arxiv.org/abs/2203.16406)
- Suphx（麻将）：oracle 先用全部特征（含他家手牌、牌山）训练，再用 Bernoulli dropout 矩阵逐步去掉完美信息特征（保留概率 γt 从 1 降到 0），最终变成普通 agent。之后继续训练时，学习率降为十分之一，并拒绝重要性权重过大的样本，否则训练不稳定。论文明确写「simple knowledge distillation does not work well」，因为信息有限的普通 agent 难以模仿 oracle。消融只以图表形式给出，没有文字数值 — [Suphx, arXiv 2003.13590](https://ar5iv.labs.arxiv.org/html/2003.13590)
- sts-rl-agent：BC 的老师（MCTS）使用真实的未来抽牌顺序，学生的训练准确率上限约 0.44，DAgger 也无效，作者认为「标签不可学」 — [sts-rl-agent](https://github.com/destire-mio/sts-rl-agent)
- PIMC（完美信息蒙特卡洛采样）的理论缺陷是 strategy fusion 和 non-locality。Long 等（AAAI 2010）用 leaf correlation、bias、disambiguation factor 三个性质来刻画 PIMC 何时有效：**disambiguation（隐藏信息被揭示的速度）越高，PIMC 越接近完美信息博弈，表现越好** — [Long, Sturtevant, Buro, Furtak, AAAI 2010](https://ojs.aaai.org/index.php/AAAI/article/view/7562)
- 对手预测类的显式信念：Bursztein 用 bigram 共现（忽略顺序）预测 Hearthstone 对手接下来的牌，第 3–5 回合排名第一的预测准确率 >95%（第 5 回合 96.2%，第二名 91.69%）；第 2 回合第一预测 66.3%；取 10 张时仅约 23% 正确。约 5 万场录像，超过 1 万场后结果稳定 — [Bursztein 博客](https://elie.net/blog/hearthstone/predicting-hearthstone-opponent-deck-using-machine-learning/)；[论文 PDF](https://elie.net/static/files/i-am-a-legend-hacking-hearthstone-using-statistical-learning-methods/i-am-a-legend-hacking-hearthstone-using-statistical-learning-methods-paper.pdf)
- Neow 项目（STS1，路线图阶段，无结果）明确主张：实体按集合编码，并为抽牌顺序等隐藏信息维护信念状态；战斗计划用「洗牌确定化 + 网络剪枝的浅层 MCTS」，每步约 1 秒 — [No-World/Neow](https://github.com/No-World/Neow)

### Inferences
- 在 STS 中，抽牌堆的**构成**本来就是玩家可以查看的公开信息（这是游戏机制常识，本次检索未单独找到出处），所以把抽牌堆按集合编码不算「信念特征」，而是必要的观测；真正的隐藏量是**顺序**。对洗牌后均匀随机的抽牌堆，「下一抽是 X 的概率」=「X 在抽牌堆中的数量 / 抽牌堆大小」，网络可以从计数特征自行算出。是否需要显式提供概率特征，没有直接证据，可以作为便宜的消融实验来测。
- 本项目有「完美信息求解器 + 精确模拟器」，最契合的外部方案是 **PerfectDou 式的非对称 actor-critic**：critic 额外输入真实的抽牌顺序、敌人后续招式 RNG，甚至求解器给出的「完美信息掉血」，actor 只看合法观测。critic 只在训练时使用，不会造成部署时的信息泄露，还能大幅降低 advantage 的方差（推断，PerfectDou 和 Suphx 均支持「完美信息帮助训练」）。
- 应避免直接用 clairvoyant 求解器的动作做 BC 标签（Suphx 与 sts-rl-agent 两个独立证据）。如果要利用求解器，可以：(a) 在 K 个重采样世界上分别求解，取期望价值最高的根动作作为标签，即 PIMC 标签，受 strategy fusion 影响但可学；(b) 只用求解器的价值作 critic 目标或辅助目标；(c) 仿照 Suphx，先给 actor 完美信息再逐步 dropout。
- STS 战斗的隐藏信息（下一回合抽什么、敌人下一招）每回合都会揭示，disambiguation 较高，按 Long 等的结论，PIMC 类方法在这种结构上相对有效。这与本项目已经采用 PIMC 一致（推断）。
- 敌人招式：STS 的敌人意图在本回合可见，但后续几回合的招式分布可能取决于 AI 规则和 RNG。没有找到「给网络提供敌人招式概率」的消融证据。

### Gaps
- 没有找到任何卡牌游戏里「显式抽牌概率特征 vs 仅计数特征」或「敌人招式概率特征」的消融实验。
- Suphx 和 PerfectDou 的收益数字来自作者自报，未见独立复现；Suphx 的 oracle guiding 消融没有文字数值。

## 问题五：数据增强、对称性（手牌/牌堆的顺序不变性）、规范化

### Takeaway
成功的系统主要靠**网络结构**获得顺序不变性：对牌堆和墓地做 mean 池化、多重集表示、实体图 + 节点打分，而不是靠数据增强（随机打乱手牌顺序）。没有找到在卡牌游戏中把「排列增强」作为独立技巧并报告收益的工作。

### Cited Findings
- ByteDance Hearthstone 对牌库、墓地使用 card embedding + mean 池化 — [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)
- Dominion 使用基于多重集的表示 + Geometric Deep Learning，以及适配可变大小动作集合的 SAC — [Gerigk & Engels, AIIDE 2023](https://ojs.aaai.org/index.php/AIIDE/article/view/27518)
- MageZero 用带类型的实体图 + 只追加的哈希词表（新卡无需重训），动作就是图中的节点，因此没有固定槽位顺序 — [MageZero](https://github.com/WillWroble/MageZero)
- Bursztein 有意使用「bag of bigrams」，忽略顺序，理由是牌随机抽到，且同一回合内的出牌顺序常常是任意的；trigram 反而更差，可能因为约束过强 — [Bursztein 博客](https://elie.net/blog/hearthstone/predicting-hearthstone-opponent-deck-using-machine-learning/)
- ByteDance Hearthstone 的另一种「增强」是探索层面的：随机让前 n ∈ {0,1,2,4} 步选牌完全随机（概率 0.5/0.25/0.125/0.125），胜率与 b1 持平，但构筑更「像人」— [arXiv 2303.05197](https://arxiv.org/pdf/2303.05197)
- LoCM 的 RL 实验：训练时可用的卡组池越大（32→1024），最终胜率越低（BC 预训练版 0.904→0.542），说明状态分布多样性与专精之间存在取舍 — [arXiv 2404.16689](https://arxiv.org/pdf/2404.16689)

### Inferences
- 本项目已用 token 集合（attention 本身对排列等变），顺序不变性主要取决于是否加了位置编码，以及池化方式。对 draw/discard/exhaust 这些无序区域，不应带位置信息；手牌顺序在 STS2 中通常不影响规则（个别卡牌效果可能与位置有关，需要按规则核对），因此可以不带位置。对未知顺序的抽牌堆，保持集合形式即可。
- 对专项模型，更有价值的「增强」可能是**起点分布**：利用模拟器从快照启动，对第三幕双 Boss 的入场状态（卡组、遗物、血量、药水）做重采样或扰动，扩大起点覆盖。LoCM 的数据显示分布越宽越难，所以分布宽度需要和专项目标相匹配（推断）。
- 规范化（canonicalization）：同名同升级的卡在集合中可以合并为「卡 + 数量」，从而减少 token 数并消除重复 token 的排列冗余。这与 Dominion 的多重集思路一致（推断，未见直接消融）。

### Gaps
- 未找到卡牌游戏中「随机排列手牌/牌堆 token 作为数据增强」的实验或收益报告。
- 未找到 Deep Sets / Set Transformer 类结构在卡牌 RL 中与「带位置编码」结构做对照的结果（本次未检索到可引用的卡牌游戏专项研究）。
