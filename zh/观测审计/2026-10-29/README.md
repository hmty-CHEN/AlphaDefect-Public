# 观测审计工作区

本目录独立保存实体索引、排查登记、微型复现脚本和原始结果。审计由主智能体与一个状态审查子智能体协作完成。没有修改训练实现、配置、检查点或服务进程。

先看 [归零结论](归零结论.md)，完整逐项记录见 [排查清单](排查清单.md)。[首轮结论](本轮结论.md)保留为历史快照。

第二轮已把首轮 8 个未决项全部收口：3 项新增确认、4 项可选特征、1 项范围内排除。**待核查为 0，不等于缺陷已修复。** 用户已提交修改计划的旧发现保留原证据，并单独标记提交状态。本轮资料位于 `round2/`，包含修改前登记快照、静态结论、运行探针及原始结果。

## 本轮边界

- 扫描 596 张卡牌、268 种能力、300 件遗物、65 种药水、23 种附魔、7 种苦痛、5 种充能球、121 种怪物、68 种事件源码定义。
- 批量扫描用于发现候选。逐项调查按效果机制归并为 47 项，不宣称测试了所有实体组合。
- “高／中／低”是基于实现的排查先验，不是计算出的错误概率。
- “确认”可能是运行确认或源码确认，两者在登记中分开。未构成整帧碰撞的测试，不声称两个局面完全相同。
- 运行复现使用游戏 v0.111.0、当前已部署的观测格式 v14，在独立低优先级进程执行。本机另一会话同时开发 v15；对应静态源码已另行核对并记录哈希，没有由本审计构建或部署。
- 千种子统计取冻结的 v81243 旧分支（1,000 局、682,802 个决策点），不是当前回退后模型的能力评估。
- 首轮曾留下 7 项待自然场景复现、1 项口径问题；第二轮已分别收口，详见 `round2/closures.json`。没有将未证明的整帧碰撞包装成已证实故障。

## 复现方式

从已配置且平台匹配的项目环境运行。脚本只通过 `reset`、`step` 和内存玩家快照构造独立场景，不打开训练检查点，也不连接采集队列。

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=python .venv/bin/python < 观测审计/2026-10-29/probes/behavior_probe.py
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=python .venv/bin/python < 观测审计/2026-10-29/probes/followup_probe.py
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=python .venv/bin/python < 观测审计/2026-10-29/probes/momentum_recovery_probe.py
```

`inventory.py` 使用本机已有反编译源码路径；`replay_coverage.py` 使用租用机已有回放路径。两者的路径都写在脚本中。Windows 可直接阅读本目录；这些 Python 命令的实际验证环境是 WSL／Linux，不代表 Windows 依赖已经配置。

后续新增排查应追加唯一 ID、先验理由、读取版本、实际验证结果及未决条件。已有项目若修复，保留原始证据并登记修复版本，不覆盖成“从未出错”。
