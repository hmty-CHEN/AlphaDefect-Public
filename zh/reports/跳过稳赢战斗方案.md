# 跳过稳赢战斗方案：整局训练里用预测结果代替稳赢的普通战与精英战

日期：2026-11-11。对象：静默猎手（猎人）。依据：[战斗结果预测检验](战斗结果预测检验.md)、[战斗结果模型复测](战斗结果模型复测.md)。

用户最初的设想是整局训练里所有战斗都换成预测。复测表明这样做不行：Boss 战的逐局面误差约 10–12 个百分点，单张牌改动的误差比约 0.6，局外策略会学到这些误差。本方案只取其中稳妥的一半：开战预测胜率很高的普通战和精英战不打，直接按预测结果结束；Boss 战和其余战斗照常真打。目的是用同样的算力多跑整局，不指望提高信噪比。

## 一、收益与边界

数字来自 1,038 局真打（第 24,020 版，出手同训练采集）：

- 一局平均 888 步，其中战斗 775 步。
- 开战预测胜率 ≥ 0.995 的战斗占 82.9%（16,923 / 20,425），实际只输了 8 场。
- 去掉 Boss 战后，这类普通战和精英战占整局步数约 55%，平均每场 26–49 步。

| 设置 | 每局省下的步数 | 同样算力多跑的整局 |
|---|---|---|
| 这类战斗全部跳过、所有整局都参与 | 约 55% | 约 2.2 倍 |
| 每场以 80% 的概率跳过，另留 25% 的整局完全真打（推荐的起点） | 约 33% | 约 1.5 倍 |

- **跳过的部分**：输赢几乎确定的战斗，所以输赢直接按赢处理。
- **仍要预测的**：掉血多少、用了哪几瓶药水，这两项会带到后面的战斗。
- **不跳过的部分**：Boss 战、问号房和事件里开的战，以及黑名单里的遭遇（见第三节）。
- **对信噪比几乎没有帮助。** 这类战斗的输赢彩票只占整局通关方差的很小一部分；第三幕两个 Boss 的 28% 一点没动。
- **不变的部分**：常规评测（始终真打、贪心）、战斗练习、Boss 战。

## 二、怎么结束一场被跳过的战斗（引擎）

新增一个请求，只在整局模式、战斗中的顶层出牌决策时可用，其他时候报错：

```
{"op": "resolve", "hp": 战后血量, "max_hp": 战后最大生命（可省）, "potions": [要去掉的药水栏位]}
```

步骤：

1. 对每个活着的敌人调 `CreatureCmd.Kill(敌人, force: true)`，再 `Pump.RunUntilIdle()`。引擎里“连续 8 回合无进展判输”已经用同样的写法结束战斗（`RunSession.CombatDecision`）。死后会分裂、召唤的敌人，循环杀到没有活的为止，设上限，超过就报卡住。
2. 战斗结束后，游戏照常走胜利流程：战斗结束时触发的遗物效果、奖励界面、爬层都不变。
3. 等这些跑完，再把血量、最大生命设成请求里的值，去掉指定栏位的药水，然后返回下一个决策（奖励界面）。

血量放到最后再设，是因为训练标签量的就是“战斗结束后第一帧”的血量，已经包含战斗结束时的回血等效果；先设血量再结束战斗，这些效果会算两遍。

**与真打不一致、要测出来的地方**：

- 每回合、每打一张牌才推进的遗物计数器不会走。
- 战斗中途触发的永久效果会丢，例如升级牌。
- 杀敌时触发的死亡效果（例如对玩家造成伤害）照常发生，但血量最后会被覆盖。

这些都靠第六节阶段 0 的保真测试量出来，再决定要不要拉黑相关的遭遇或遗物。

只新增这一种请求，不改观测格式，不改其他请求的行为。部署前要做新旧引擎同种子整局逐帧比对：不调新请求时，帧必须逐字节相同。

## 三、跳不跳、结果怎么定（采集端）

在整局模式的战斗第一帧，同一次前向顺带算出辅助头的输出。满足下面全部条件才跳过：

1. 房间是普通战或精英战，而且是选路后直接进入的（不是问号房或事件里开的战）。
2. 开战预测胜率 ≥ 0.995（阈值可调）。
3. 遭遇不在黑名单里。初始黑名单来自稳赢、赢下的非 Boss 战（147,156 场）里查到的永久变化：
   - 卷轴怪（SCROLLS_OF_BITING_*）：会咬掉最大生命，占最大生命减少的 99.7%（4,133 / 4,144）；
   - 偷牌跳蚤（THIEVING_HOPPER_*）：会偷走一张牌，占牌组变化的 39%（4,349 / 11,032）；
   - 会偷金币的几种敌人：GREMLIN_MERC_NORMAL 等，阶段 0 按金币减少的比例定名单。

   之后由真打的战斗持续统计：某个遭遇的永久变化比例超过 1% 就加进黑名单。
4. 这一局不是“完全真打”的整局（开局时以 25% 的概率指定），再按 80% 的概率抽中。

**跳过时的结果**：

- **掉血**：辅助头预测值减去校准偏差，再加一个按分层抽的残差。
  - 校准偏差：这类战斗里，辅助头系统性地少估掉血。

    | 层 | 少估（最大生命的百分比） |
    |---|---|
    | 第一幕精英 | 1.72 ± 0.52 |
    | 第一幕普通战 | 0.72 ± 0.16 |
    | 第二幕精英 | 0.67 ± 0.63 |
    | 第二幕普通战 | 0.35 ± 0.24 |
    | 第三幕精英、普通战 | 不显著 |

    整局累计约 9.5%，不扣掉的话，跳过后进 Boss 时会比实际多约 9.5% 最大生命的血。偏差按（幕，房间）用最近真打的同类战斗滚动估计。
  - 残差：从同一层、同一档预测值的近期真打残差里随机抽，让战后血量有真实的离散。
  - 结果截在 [1, 最大生命] 之内。
- **药水**：每瓶按预测的用掉概率抽签。这需要第四节新加的药水输出；它上线、校准合格之前，不跳过身上有药水的战斗。
- **最大生命**：减少的来源已由黑名单去掉。增加的有 1,284 场，占这类战斗的 0.9%，多出现在精英战，多半是战斗结束时触发的效果，第二节第 2 步照常会发生，阶段 0 核实。

**训练数据怎么处理**：

- 被跳过的战斗不产生任何训练步，开战那一帧也不进轨迹。
- 战斗的辅助标签只来自真打的战斗。
- 整局分段的步数计数，要把跳过的战斗按这一层的平均步数补上。分段按 64 步切，跳过战斗后同样 64 步会跨更多层，局外决策的自举距离就被拉长了，而第 12 条（分段 64 → 256）刚证明拉长有害。

## 四、学习端与模型

- **新加两个只读的输出头**：每瓶药水用掉的概率（在药水记录上逐瓶输出），以及战后血量的分布（HL-Gauss，41 格）。
  - 两个头都只读主干表示的 detach 副本，不往主干回传梯度，对策略和价值的学习没有影响。
  - 标签在采集端算：药水按开战帧与战斗结束后那一帧里我方药水的数量差，血量取战斗结束后那一帧。
  - 复测时整网微调版的药水预测 AUC 0.92、校准良好，说明能学会。
  - 有了血量分布头，可以替代第三节按层抽残差的办法。第一版先用残差抽样，分布头训好、校准合格后再换。
- **局外优势、价值目标、奖励都不改。** 整局奖励只看爬层、打过 Boss 和最终输赢；猎人配置里按战斗掉血、用药扣分的塑形项系数都是 0，跳过非 Boss 战不影响奖励的计算。
- **每版仍收 131,072 步。** 跳过之后，一版里的整局片段和局外决策会变多，局外决策约多 1.5 倍。这相当于把局外样本加大，和第 11 条“加大每版数据”同一方向。

## 五、看板与护栏

**新增统计**：

- 跳过的场次与占比。
- 按层的掉血校准偏差，以及校准后的残差均值。
- 药水输出的校准与 AUC。
- “完全真打”与“允许跳过”两类整局各自的通关率、进 Boss 时的血量和药水。

**护栏（满足任一条就停用跳过、退回原样）**：

- 常规评测最近 12 轮通关率比上线前低 2 个百分点以上。
- 允许跳过的整局里，进第三幕 Boss 时的平均血量与完全真打的整局相差超过 3% 最大生命。
- 校准后，任一层的掉血残差均值超过 ±0.5% 最大生命。
- 引擎在新请求上报错或卡住的比例超过 0.1%。

**效果怎么读**：沿用第 11、12 条的读法，满 500 版时与上线前同样长度的一段比：

- 评测通关率；
- 完全真打整局的通关率；
- 每小时版数；
- 局外决策的熵。

## 六、分阶段执行

| 阶段 | 内容 | 对训练的影响 |
|---|---|---|
| 0 | 引擎新请求；在 B 的单独目录用测试脚本真打几千局“允许跳过”的整局，量保真度：永久变化、奖励流程、卡住与报错、实际省下的步数与速度；新旧引擎逐帧比对 | 不影响；只在停训窗口或空闲时跑重活 |
| 1 | 采集端加新输出头的标签和统计，学习端加两个只读头；不跳过任何战斗，只看校准 | 停训约 10 分钟部署，之后照常训练 |
| 2 | 打开跳过：先跳过概率 50%，100 版没碰护栏再升到 80% | 再停约 5 分钟部署；之后按第五节读效果 |

部署和重启归猎人会话管。每个阶段上线前都要用户批准，并记进猎人决策记录。

## 七、风险

- **保真度。** 立即结束战斗会丢掉战斗中途的效果，包括遗物计数、中途升级牌。阶段 0 量不准的话，局外策略会慢慢高估持有这类遗物、牌的价值。“完全真打”的整局提供一个不受影响的对照，可以监测这种漂移。
- **战斗策略在这类战斗上练得少了。** 每局真打的普通战减少，战斗策略在普通战上省血的本事可能退步。普通战练习、完全真打的整局、20% 不跳过的场次这三处都还在练，看板上看普通战掉血的走势。
- **更多整局不一定换来更快的进步。** 现在的瓶颈在局外决策的信号小、噪声大。多跑整局能增加独立样本，但第 11 条那样的收益不保证能复现。
- **工程量**：引擎约 100 行，采集端约 200 行，学习端两个头加统计，还有三次部署。

## 需要用户决定

1. 是否按本方案开始做阶段 0。阶段 0 只写引擎新请求和测试脚本，不动训练；重活跑在停训窗口或空闲时。
2. 推荐的起点参数是否可以：跳过概率 80%、完全真打的整局 25%、胜率阈值 0.995、只跳过普通战和精英战。
