# M2 准备报告：面向租用机的训练系统（2026-10-24）

结论：Defect 战斗课程的 PPO 训练系统已经完成，并在本机端到端验证了学习效果：20 分钟、约 20 万步后，策略在固定评测集上明显强于随机策略。系统按“显卡推理与学习 + 多核 CPU 跑引擎”的租用机设计，规模参数全部可配置。标定脚本和部署脚本已备好，在本机完整走通。租用机的配置确定后，上机先跑 `setup.sh`，它会自动标定并给出训练配置。

## 一、训练系统

```text
学习进程（GPU）                     采集进程 × A（各管 E 个引擎）
  PPO 更新（GAE，KL 提前停止）   ←轨迹（拼接数组）—  批量推理（GPU）→ 选动作 → 引擎
  发布权重到 /dev/shm             —权重、课程进度→    按版本号拉取
  课程进度自适应
```

| 部件 | 文件 | 要点 |
|---|---|---|
| 网络 | `python/sts2rl/model.py` | 只有核心记录进注意力层（全局、生物、手牌、供选择、充能球、药水）；牌堆、遗物按区域汇总为 5 个记录；能力加到所属生物上。候选打分；价值网络另读“抽牌堆顶部”的特权汇总。宽度、层数可配，默认 d=128、2 层（约 2M 参数，其中词表嵌入约一半） |
| 组批 | `python/sts2rl/features.py` | 拼接格式（`Ragged`）跨进程传输，组批全向量化，与逐条组批结果逐项一致 |
| 课程 | `python/sts2rl/curriculum.py` | 进度 0→1：从“第一幕普通怪、初始牌组”到“三幕全部遭遇、成型牌组”；牌组、遗物、药水、血量随机抽取。A10 初始牌组带 Ascender's Bane。最近胜率 > 75% 加难度、< 45% 降难度 |
| 采集 | `python/sts2rl/actor.py` | 异步收发，凑批推理；队列满时阻塞（反压）；学习进程退出时自行退出 |
| 学习 | `python/sts2rl/train.py` | PPO（γ=1，λ=0.95，裁剪 0.2，KL 超过 1.5×0.02 时提前结束本轮）；丢弃策略版本落后超过 3 的轨迹；检查点与续训 |
| 奖励 | `python/sts2rl/config.py` | 胜 +1、负 −1，加上（结束血量 − 开始血量）/ 最大生命，每用一瓶药水 −0.05 |
| 评测 | `python/sts2rl/evaluate.py` | 固定种子的评测集，贪心或采样，按幕和遭遇类别统计 |
| 标定 | `python/calibrate.py` | 测引擎、推理、学习、采集进程四项吞吐，输出推荐配置 |
| 部署 | `tools/remote/pack.sh`、`setup.sh` | 打包代码与游戏程序集；租用机上安装 .NET 9、Python 虚拟环境与 PyTorch（默认走 pip 镜像），编译、冒烟测试、标定 |

## 二、本机验证

**学习效果**（2 个采集进程 × 5 个引擎，CPU 学习，约 20 分钟、20 万步，贪心评测，各 400 场）：

| 评测集 | 随机策略 胜率 / 平均掉血 | 训练后 胜率 / 平均掉血 |
|---|---|---|
| 课程起点（第一幕普通怪，初始牌组） | 80% / 54% | 99.75% / 23% |
| 课程进度 0.25 | 45% / 55% | 68% / 38% |

**健壮性：**
- 学习进程被强行终止后，采集进程和引擎在 4 秒内全部退出。
- 可从检查点续训。
- 加反压后不再丢弃轨迹，策略滞后从约 3 个版本降到约 1.5。
- 部署脚本在临时目录完整走通，打包后的引擎整局指纹与开发目录一致。

## 三、为租用机做的优化

| 优化 | 效果 | 验证 |
|---|---|---|
| 地图生成：重写重复子段检测（跳过已见过的子段） | 每幕约 44 ms → 约 20 ms | 900 张地图与原算法逐项一致；整局指纹一致 |
| 观测序列化：整块内存拷贝 | 编码约 0.15 ms/步 | — |
| 网络只对核心记录做注意力 | CPU 上推理约 4 倍、训练约 3 倍（同宽度） | — |
| 组批全向量化 | 约 3 倍；采集进程 Python 侧每秒可处理 5–10 万个决策 | 与逐条组批逐项一致 |
| 多采集进程 + 异步收发 + 反压 | Python 侧不再是瓶颈；不产生会被丢弃的数据 | — |

本机标定（快速模式，课程进度 0.6）：引擎 14 进程约 2800 决策/秒；CPU 推理约 5600–8700 决策/秒；CPU 训练约 2200 样本/秒。推荐配置预测约 730 决策/秒，与实际训练速度（约 800）吻合。

## 四、到租用机上才能决定的事

1. 引擎进程数、采集进程数、批大小：由 `calibrate.py` 按实测给出。
2. 网络规模：显卡上用同样样本量对比 d=128/2 层、d=256/4 层等几档（技术路线 12.1 节的扩容对比）。
3. 学习率、批大小与课程节奏：先用推荐配置跑通，再按学习曲线调整。
4. CUDA 路径还没有在真实显卡上跑过：代码只用标准的 `.to(device)`，第一次上机先用 `setup.sh` 的冒烟测试确认。

## 五、上机步骤

```bash
# 本机
bash tools/remote/pack.sh ~/            # 生成 sls2-deploy-日期.tar.gz（约 40 MB）
scp ~/sls2-deploy-*.tar.gz <租用机>:~/
# 租用机
tar xzf sls2-deploy-*.tar.gz && bash sls2/tools/remote/setup.sh
CONFIG=~/calibration_train_config.json bash sls2/tools/remote/start_train.sh   # 运行目录 ~/.local/share/sls2/runs/defect
（实际上线时的调整、守护与看板见 M2训练上线报告.md）
```
