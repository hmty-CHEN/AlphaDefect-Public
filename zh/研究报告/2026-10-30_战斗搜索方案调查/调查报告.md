# 战斗搜索调查：MCTS 的潜力，以及比“贪心”更好的候选

日期：2026-10-30。范围：项目内的搜索实验与基础设施（决策记录第 125、131、132、136、145、152 条，`AlphaZero式搜索方案.md`，`技术路线.md`，`后续计划.md`，`tools/mcts_eval.py`，`python/sts2rl/azmcts.py`），外加公开文献和社区项目。本次只读代码与记录，没有跑新的对局，没有改训练。

**第 0 步诊断已做完，结果见同目录 `第0步诊断结果.md`**：现模型（第 108,583 版）在双 Boss 诊断卷 175 题上，搜索 77 对贪心 64（+7.4 ± 2.9 个百分点，p = 0.019）；价值头与推演得分相关 0.92，适合当叶子；预算 ×4 的趋势为正但只有 30 题，没有证据。下文第一至第六节写于诊断之前，其中“搜索对现模型多半有用”一条已被这次结果支持，其余判断以诊断结果为准。

文中“估算”是我按已有数字推的，没有实测；“旧模型”指第 40,072 版（搜索实验时的主线），“现模型”指第 107,000 版前后。

## 一、结论

1. **搜索对现模型多半有用，但项目内的证据是旧模型的，而且只在离线评测里。** 第 40,072 版上，确定化推演式改选在第二幕 Boss 考卷上 +6.2 ± 1.7 个百分点，第三幕 Boss 上 +1.2 ± 1.3 到 +2.3 ± 2.0（不显著）。之后主线从 40,072 版训到 107,000 版，通关率从约 10% 到约 53%，搜索的收益在强得多的策略上是更大还是更小，没有数据。
2. **“用不用 MCTS”不是最大的问题，三个前提才是。**
   - 状态复制：C# 引擎只能“从战斗开头重放动作”，每次模拟约 0.19 引擎秒（估算）；Rust 引擎能复制，但已归档，观测编码停在版本 10，现在训练用 15。
   - 叶子估值：价值头在第三幕 Boss 局面上够不够准，没有专门测过。
   - 能不能用到直播：实机桥接不传种子、不能读写状态，无头引擎也没有“从战斗中途局面导入”的接口。所以搜索想让直播受益，只有两条路：把搜索蒸馏回网络，或者做实机状态导入。
3. **有比“一步贪心推演”更合适的算法，但它们多数是同一家族的改进，不是另起炉灶。**
   - 低模拟预算下，Gumbel 式搜索（序贯减半 + 补全 Q 的策略改进）比 PUCT 稳；
   - 改选规则用“KL 正则化”（π′ ∝ π·exp(Q/λ)），可以取代现在的“2 个标准误”硬阈值，也直接给出蒸馏目标；
   - 一回合要打好几张牌，Hearthstone 一类游戏里常见的做法是回合级（宏动作）搜索或在线演化，值得作为备选。
4. **建议先花约 1–2 天做“第 0 步诊断”（4.0 节），再决定上哪个候选。** 它回答三件事：现模型上旧搜索还有没有收益；加大搜索预算能涨多少（搜索天花板）；价值头能不能当叶子。三个答案会直接淘汰或推荐后面的候选。
5. **不建议重开的方向**：局外选牌前瞻（决策 125，−0.84 层）、选路风险展开（决策 152，无收益）；以及近期上学习型世界模型（Stochastic MuZero 类）。

## 二、项目内现状与证据

### 2.1 “贪心”指什么

评测、千种子复测、直播都是每步取网络概率最高的候选，没有前瞻；训练采样。搜索实验里的“贪心推演”是另一个意思：把候选走一步后，让同一个网络贪心打完战斗，当作这个候选的得分。下文凡说“贪心”，指前者。

### 2.2 已做过的搜索实验

| 实验（决策记录） | 设置 | 结果 |
|---|---|---|
| 确定化推演，只看输赢（125 第一版） | 第三幕 Boss 256 题，旧模型 | 47 → 46，−0.4 ± 1.7 |
| 加部分分（125 第二版） | 同上 | 46 → 46，0.0 ± 1.9；96 题诊断：1,968 次搜索改选 1,004 次，一半的步被噪声改掉 |
| 配对 + 2 个标准误才改（125 第三版） | 第三幕 256 题 | 47 → 50，+1.2 ± 1.3，改选约 10% |
| 同上 | 第二幕 256 题 | 117 → 133，**+6.2 ± 1.7**，多赢 18 少赢 2 |
| 推演次数翻倍（132 act3v4）与价值叶子 12 步（act3v5） | 第三幕前 131 题 | 两者都 +2.3 ± 2.0，逐题对比 0.0 ± 2.2；v4 慢一倍多 |
| 选牌的牌组前瞻（125） | 185 个种子整局 | 平均层数 −0.84 ± 0.70，叫停 |
| 搜索蒸馏（131，136，138） | A 产标签，B 辅助损失 | 只跑了几千条标签就因 Rust 引擎开发暂停，随后关掉；没有结论 |
| AlphaZero 式 PUCT 搜索（145） | 每步 32 次模拟，第二、三幕各 20 题，C# 重放 | 第二幕 16/20 对贪心 14/20，第三幕 10/20 对 10/20；样本太小，只验证了算法正确 |
| 选路风险展开（152） | 房间结果模型 + 血量动态规划，进阶 10 配对 | 无收益，不采用 |

从这些数里能读出几件事：

- **配对（共同随机数）和显著性门槛是必要的。** 不配对、不设门槛时，搜索改了一半的步，收益为 0。
- **第二幕 Boss 上搜索明显有用，第三幕上看不出。** 当时的解释是第三幕的贪心推演多数会输（贪心实际胜率约 0.2），分不出候选好坏。换成价值叶子后没有变好，说明限制不只是推演信号稀疏。可能的原因（假设，未检验）：价值头在这些局面上不准；一步改进已经到顶，要靠更深的树；候选只取前 4 个（各至少 2%）漏掉了好动作；第三幕不少局面在入场时就已经输了。
- **上界很大，但是偷看了随机数的上界。** 求解器（完全信息）在第三幕 Boss 局面上能赢约 46%，当时的模型约 20%；第二幕 75% 对 62%（后续计划第六节，10-27）。后续计划“暂不做”里已经写了：要对照得用信息边界相同的搜索。搜索能拿到这个差距的多少，要靠第 0 步的预算曲线才能知道。

### 2.3 瓶颈在哪里，改善一点值多少

第 107,000 版复测（决策记录 201 补记）：通关 52.8%；进第三幕 Boss 84.5%，打过第一个 88.4%，进第二个后通关 70.7%（0.845 × 0.884 × 0.707 ≈ 0.528）。最近 15 次评测的死亡里，第三幕 Boss 约占三分之二。

据此的敏感度（估算，假设各段条件胜率独立）：

| 提高 | 通关率变化 |
|---|---|
| 第三幕第一个 Boss 条件胜率 +1 个百分点 | 约 +0.60 个百分点 |
| 第三幕第二个 Boss 条件胜率 +1 个百分点 | 约 +0.75 个百分点 |
| 两个 Boss 分别 +3、+5 | 约 +5.5 个百分点 |

注意旧实验的考卷比实际对局难：第二幕 Boss 考卷贪心只赢约 46%，评测里约 80% 以上。所以“+6.2”这类数字换算到整局，应该打折。

### 2.4 基础设施

| 部件 | 现状 |
|---|---|
| C# 真引擎 | 有 `reseed`（换玩家看不到的随机数、重洗抽牌堆），没有战斗中途的复制。一次往返可以“开局 + 重放 + 换随机数 + 走候选”。实测每道题约 31 秒（48 个引擎、6 题并行、每步 32 次模拟），折合约 0.19 引擎秒每次模拟（估算，端到端：含 Python 调度、观测编码、网络推理；本机实测引擎裸速度约 1.3 ms/步，观测编码另加约 1.2 ms/步，所以重放本身只占其中一部分，具体比例没有拆开） |
| Rust 引擎 | 战斗规则对拍 98.4%，编码每帧约 3.2 微秒，可复制；2026-10-28 归档，观测停在版本 10（现为 15，差五个版本的新字段） |
| `azmcts.py` | SO-ISMCTS + PUCT + 可用性计数 + 动作键 + 虚拟损失，与后端无关；C# 重放后端 `tools/az_eval.py` 已核对正确 |
| `mcts_eval.py` | 推演式改选（共同随机数、逐轮减半、配对门槛） |
| 价值头 | 战斗和局外各一个；价值头有特权输入（抽牌堆真实顺序），策略头没有 |
| 评测基础 | 双 Boss 诊断卷 175 题（第三幕连打）；旧第二、三幕考卷停用但文件在；千种子复测 |
| 实机桥接 | 不传种子与随机数，没有 `reset/reseed/state` 之类的请求；直播里无法直接做搜索 |

### 2.5 一个要先弄清的技术点：这里的“隐藏信息”其实很好处理

战斗里玩家看不到的只有抽牌堆顺序、敌人以后的随机选择、战斗中随机生成的内容，而牌堆里有什么牌是公开的。`reseed` 重洗牌堆、换随机数，相当于从“公开历史下的真实后验”里采样，不需要像 Hanabi 那样学一个信念模型。这有两个含义：

- 单观察者搜索（SPARTA 式：自己搜索，其余按基线策略）在这里可以用精确信念，不是近似。
- 价值头的特权输入不构成偷看：它估的是“给定公开状态和这个世界的牌序，现策略的回报”，多个世界平均后是对信息边界内策略的无偏估计（`AlphaZero式搜索方案.md` 第二节的论证成立）。真正要防的是**搜索内部利用世界信息**——这正是 PIMC 的策略融合问题；SO-ISMCTS 用一棵共享的树、MAPLE 汇总多个世界的评估都是在处理它。
- 小偏差：如果某张牌让玩家“看到了牌堆顶”，`reseed` 会把这个信息洗掉（决策记录 129 的“已知抽牌堆顶部”）。故障机器人很少遇到，影响小。

## 三、公开研究给出的信息

| 主题 | 要点 | 对本项目的含义 |
|---|---|---|
| 滚动改进（rollout）与价值叶子（Bertsekas；TD-Gammon） | 用基策略做推演、一步前瞻，理论上不比基策略差（成本改进性质）；截断推演加叶子估值是 AlphaZero 与 TD-Gammon 共有的做法 [1] | 现有“贪心推演改选”就是这个家族。理论保证在精确期望下成立，推演次数少时被噪声侵蚀，所以要配对和门槛 |
| 低预算下 AlphaZero 失灵 | PUCT 在模拟数少时可能不改进策略；Grill 等证明访问次数近似一个 KL 正则化的策略优化问题，直接取其精确解在低预算更好 [2]；Gumbel AlphaZero/MuZero 用不放回采样 + 序贯减半 + 补全 Q 的策略改进，在很小的模拟数下也保证改进，DeepMind 的 `mctx` 有实现 [3] | 我们每步只能负担几十次模拟，正处在这个区间。现在的 PUCT 版（32 次）收益小，不意外 |
| 随机环境的树 | Stochastic MuZero 加“后状态/机会节点”处理随机转移，在 2048 等单人随机游戏上超过 MuZero [4]；开环（只按动作建树）规划在随机域里通常收敛到次优、不如闭环 [5] | 我们的树按动作键建，是一种折中；抽牌后手牌不同会自然分叉，但值得核对 |
| 部分可观测的单人规划 | DESPOT 用固定的一组场景（随机数流）建稀疏树，并用正则项防止对这些场景过拟合 [6]；BetaZero 把 AlphaZero 搬到信念空间 [7] | 我们的“同一组随机数比各候选”就是 DESPOT 的简化版；正则项的思路可借 |
| 改进已训练好的策略 | SPARTA：在 Hanabi 上，单人搜索对每个测试过的策略都有提升，并刷新双人纪录（24.61/25）[8]；Learned Belief Search 用学出的信念拿到精确搜索 55–91% 的收益，算力降 4.6–35.8 倍 [9] | “蓝图 + 搜索”在合作/单人隐藏信息游戏里是成熟路线 |
| 带 KL 锚的搜索 | piKL：搜索结果向基线策略收缩，防止被评估噪声带偏 [10] | 对应我们的“超过 2 个标准误才改”，但是平滑的、可微的版本 |
| 一回合多个动作 | Hero Academy、Hearthstone 上，朴素 MCTS 在“一回合很多动作”时效率差，在线演化（RHEA）和宏动作/动作链更好 [11] | 一回合出 3–8 张牌，枚举和束搜索可能比逐张建树省网络调用 |
| 单人确定性搜索 | LevinTS、PHS 用策略 + 启发式，有搜索量上界 [12] | 只适用于确定性问题，这里的随机抽牌不符合，只借“策略先验引导”的思想 |
| 训练时用搜索 | 专家迭代、MuZero Reanalyze、KataGo 的“随机搜索深度 + 策略目标剪枝”[13][14] | 蒸馏路线的做法；KataGo 的经验适合“只在关键局面深搜” |
| 无树的在线规划 | Policy Gradient Search 不建树，在搜索中在线更新模拟策略，Hex 上与 MCTS 相当 [15] | 当“复制状态”贵时的一条备选，但需要大量前向，未必比树便宜 |
| 搜索与训练的算力互换 | Hex 上每多一个数量级的训练算力，可以少一个数量级的测试算力 [16] | 主线已训练约 28 亿步；这条经验说明搜索的边际收益会随训练变强而下降，对应 2.2 节“旧模型的数不能直接用” |
| 同类 Slay the Spire 项目 | 一个 Ironclad A0 项目：模拟器自带 MCTS 打战斗，学出来的小策略管局外；6 次把 MCTS 蒸馏进前馈网络都失败（模仿准确率 0.44），作者推测“老师等于看到了抽牌顺序”[17]。另一个项目：叶子用学出的启发式，对多个抽牌未来取平均反而偏向保守路线，且不显著 [18] | 蒸馏失败的原因很可能是教师不在信息边界内——我们的 `reseed` 搜索教师在边界内，但要设计时盯住；“对未来平均偏保守”是 CRN 之外要观察的偏差 |

## 四、候选方案

下面每项都写清：做什么、依据、代价、风险、判定门槛。代价按“新写代码 / 占用算力”粗估，工作量单位是我对本项目的估计，不是承诺。

### 4.0 第 0 步：诊断套件（建议无论选哪个都先做）

目的是在花大工程之前回答：现模型上搜索值不值得；瓶颈在预算、叶子还是候选。全部用现有 `mcts_eval.py`、`azmcts.py` 与 C# 重放后端，放在 A 上低优先级跑，不动 B。

- **0a 复测旧搜索**：用现模型（如第 107,000 版）在双 Boss 诊断卷 175 题上跑推演式改选（配对、2 个标准误），与贪心逐题配对。第二幕用已停用的考卷或从复测局面新建。同时记录改选率。
- **0b 搜索预算曲线**：在 60–100 题的子集上，把首轮推演次数放大 ×1、×4、×16（以及价值叶子版同样三档），画“预算—胜率”。如果 ×16 仍不到 +3 个百分点，说明限制在叶子或基策略，不在搜索预算，后面的树搜索收益会很有限。
- **0c 价值头校准**：取 Boss 战中的若干局面（开战、每回合开始），各用 64 次重洗后的贪心推演估一个胜率，与战斗价值头的输出比较（相关、校准曲线、按回合分解）。这决定价值叶子能不能依赖。
- **0d 改选分类**：对 0a 里搜索改选了的步，按“斩杀线、挡伤、出牌顺序、能力牌/打出时机、药水”粗分类（可用观测里的预演特征和回放做半自动分类）。搜索改的是什么类型的错，决定了回合级搜索和蒸馏哪个更对症。

估算成本：决策 145 的 C# 重放后端一道题约 41 个决策、每步 32 次模拟，约 1,300 次模拟，每次约 0.19 引擎秒，合约 250 引擎秒；175 题约 12 个引擎小时。推演式改选（0a）每步的推演数不同，量级相近，预算 ×16 的档要乘 16。无需改训练。

### 4.A 推演式改选 v2：KL 正则化的滚动改进

做什么：保留现有“基策略推演 + 共同随机数”的结构，把“超过 2 个标准误才改”换成 π′ ∝ π·exp(Q̂/λ)，λ 随推演次数收缩（Grill、piKL 的做法）；候选不再硬取前 4，改为按概率阈值或 Gumbel-top-k 采样；叶子可选“价值头 + 短推演”；只在关键步搜索（最大概率 < τ，或血量/斩杀线触发），把预算集中在少数决策上。

依据：已有正的实测（第二幕 +6.2）；KL 形式是平滑版的显著性门槛，同时给出蒸馏目标（见 D）；第 0 步的预算曲线直接指导 λ 和预算。

代价：改 `mcts_eval.py` 为主，约 1–2 天；算力同第 0 步。

风险：与旧版同一家族，第三幕可能仍然看不出收益；离线评测，不直接惠及直播。

门槛：在双 Boss 卷上对贪心配对 +3 个百分点以上（约 2 个标准误），且没有退步的题类。

### 4.B Gumbel 式树搜索（替换 `azmcts.py` 的 PUCT）

做什么：根节点用 Gumbel-top-k + 序贯减半选候选，非根节点用补全 Q 的确定性策略（`mctx` 的 `gumbel_muzero_policy` 思路），保留 SO-ISMCTS 的动作键与可用性计数；抽牌/随机生成处用机会节点或按观测分叉，避免开环偏差。

依据：[2][3]；与我们每步只有几十次模拟的预算相符；树能搜到多回合深度，而推演式只走一步。

代价与后端有两条路：
- **B1：沿用 C# 重放后端，小规模。** 只做验证，几天内可得；每步几十次模拟时一道题几十秒。适合在双 Boss 卷上与 A 比。
- **B2：把 Rust 引擎观测补到版本 15，再接 PyO3 复制。** 工作量大（观测 10 → 15 的字段补齐与逐字节对拍，加战斗规则 98.4% → 更高的对拍维护），收益是模拟成本降两个数量级，能支撑训练规模的搜索。方案文档里的假设“Rust 只用于推演、真实结果仍在 C# 重放核对”降低了对规则一致率的要求，但编码必须与现网络的输入一致。

风险：价值头质量（0c）；PUCT 版 32 次模拟的 40 题实测没有可见优势，Gumbel 版能否在同预算下做到，需要 B1 先验证；B2 的工程量是项目里最大的一块。

门槛：B1 在 175 题上对 A 配对不差，且预算 ×4 时继续上升，再投入 B2。

### 4.C 回合级（宏动作）搜索

做什么：以“一整回合的出牌序列”为单位搜索。回合内用网络先验引导深度优先或束搜索，枚举合法出牌顺序（手牌 ≤ 10、能量有限，序列数可控），敌方意图可见，下一回合的抽牌用若干个重洗世界取平均，叶子是回合末状态的价值头评估。

依据：Hearthstone/Hero Academy 的经验 [11]；一回合内的主要不确定性是抽牌效果，能量和意图是确定的；网络调用次数按回合而不是按张数计。

代价：新搜索器，约 1–2 周；仍然需要状态复制（C# 重放同样贵），但每个叶子对应一回合而不是一张牌，同样预算看得更远。

风险：带抽牌效果的牌会让回合内的序列依赖随机结果（需要分叉）；价值头在“回合末、敌人尚未行动”的局面上不一定训练得好（训练时这类局面是决策点之间的中间状态）；与 B 部分重叠，且第 0d 若显示搜索改的主要是“跨回合”的错，收益会小。

门槛：先在 0d 里确认有足够多的“同回合内顺序/斩杀”类改选，再做。

### 4.D 搜索蒸馏 / 专家迭代 v2

做什么：用 A 或 B 的搜索在 Boss 局面上产标签，以 Gumbel 补全 Q 的策略（π′ ∝ π·exp(σ(Q̂))）作策略目标，以搜索根价值作价值目标，作为 PPO 之外的辅助损失；标签按产出它的检查点计龄；只在“搜索改选”或“Q 差距大”的步上加权。继承决策 131 的框架（`distill.py`、`tools/distill/`，现关着）。

依据：这是让搜索收益**到达直播和整局**的唯一现实路径（除非做 H）；KataGo 式“只在关键局面深搜”能控制成本；搜索教师在信息边界内（`reseed`），避开 [17] 的失败原因。

代价：基础设施大部分已有；标签规模估算：每 10 万个被标注的决策、每步 32 次模拟，约 170 引擎小时（0.19 引擎秒 × 320 万次模拟）。相对训练规模（约 28 亿步）很小，但是针对关键局面。

风险：
- 决策 131 之后，只产出了几千条标签就暂停，**不是失败证据**，也不是成功证据；
- 对网络来说，Boss 战里的收益要靠“看见同样类型的局面”泛化，[17] 的 6 次失败说明不能默认成立；
- 与 PPO 同时优化可能互相拖，需要 KL 护栏和单项上线（后续计划第二节的规则）；
- 价值目标会改变价值头，影响 GAE，要先在 A 的分叉上试。

门槛：A 分叉（只加这一项）在双 Boss 卷上第 1,000–1,500 版内对主线配对 +2 个百分点以上，且护栏不触发。

### 4.E 搜索分歧挖课程（学习潜力选题）

做什么：用搜索与贪心的分歧（或 Q 差距）找出“贪心打错”的 Boss 局面，作为课程选题权重（PLR 思路，后续计划第八节已列“按学习潜力选题的对照”）。不需要蒸馏标签，只需要“哪些局面有改进空间”。

代价：低；复用 A 的搜索产出；没有新训练机制，只是选题权重。

风险：分歧可能反映的是搜索噪声而不是策略错误；可以用 A 的 KL 正则化过滤。

门槛：与按输率加权（永世沙漏，决策 192）对照。

### 4.F 精确子程序（斩杀与零伤害检查）

做什么：当前手牌下枚举出牌序列，检查能否本回合斩杀全部敌人，或能否把本回合伤害压到某个门槛。把结果作为观测特征或动作掩码。

依据：观测里已有“伤害预演”“能否打死”“回合结束预演”，决策 128 的案例说明早期模型会漏；`第 0d` 若显示斩杀线类错误占比高，这个很便宜。

风险：需要引擎复制，且抽牌效果使“精确”只对已知手牌成立；很可能网络已经学到大部分。优先级低。

### 4.G 学习型世界模型规划（Stochastic MuZero 类）

做什么：训练一个战斗潜在动力学模型，在潜在空间里搜索。[4] 的方法在 2048、双陆棋上可行。

不建议近期做：卡牌效果成百上千种，模型误差会直接污染搜索；已有精确引擎，主要问题是复制成本而不是模型缺失；投入大、风险高。

### 4.H 实机状态导入（直播直接搜索的前置）

要让直播里的模型在 Steam 版游戏里搜索，需要把实机战斗局面导入无头引擎：要么实现战斗中途导入（生物、能力、遗物计数、牌堆、意图历史），要么把观察到的抽牌和敌人选择当成“已知结果”重放（观测条件重放）。两者都不小，保真风险也大；只在 D 的收益不足、而直播又明确需要搜索时再考虑。

### 4.I 其他方向（简述）

- **测试时集成/专家路由**：见 `研究报告/2026-10-30_状态路由专家集成/调查报告.md`，不重复。
- **局外搜索**：选牌前瞻（决策 125）和选路风险展开（决策 152）都没有收益，不重开；房间结果模型保留作诊断。
- **纯进化/NRPA 类**：NRPA 与 Levin/PHS 面向确定性单人问题，抽牌随机性让它们不直接适用；在线演化（RHEA）可作为 C 的替代搜索器，但我们已经有强先验，没有明显理由放弃树/束搜索。

## 六、建议顺序与判定门槛

1. **先做第 0 步（1–2 天，放 A 上低优先级）。** 不动 B，不影响训练。
2. 根据结果走：
   - 0a 有正收益（≥ +3 个百分点）且 0b 随预算上升：做 A，同时用 B1 在小题集上验证 Gumbel 树；通过后决定是否投 B2；
   - 0a 正、0b 平：叶子或基策略是瓶颈，先查 0c，转 D（用已有标签流程小规模验证）或改进价值头；
   - 0a 约为 0：现模型在这些局面上的“可搜索空间”已经很小，转 E（用搜索找难题）和学习侧改进，搜索只保留为评测工具。
3. D 在 A 分叉上单项上线，用双 Boss 卷与千种子复测判定，遵守“一次一项”的规则。
4. H、G 不排期；直播确实需要实机搜索时再回头评估 H。

## 七、需要你选择的几件事

1. 目标偏重：想看到“搜索版明显强过贪心”的离线证据（走 A、B），还是想让**直播/整局**直接变强（走 D，必要时 H）？
2. 算力：第 0 步和 A 要占 A 机一段时间（A 目前 CPU 基本满，评测与采集共用）。接受低优先级慢跑，还是需要暂停一部分评测或采集？
3. Rust 引擎：B2 需要把观测补到版本 15 并重新对拍。愿不愿意把已归档的 Rust 引擎重新启用？第 0 步的结果可以作为依据，建议先不决定。
4. 蒸馏的先决条件：是否接受 D 的价值目标会影响主线价值头（建议只在 A 分叉里试，不进 B）。
