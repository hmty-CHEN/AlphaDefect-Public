# 搜索测试结果：搜索能多赢多少，蒸馏有没有用

日期：2026-10-31。用户：“请在合适的时机暂停训练，把两机的所有性能用于搜索测试……第一目标，测试搜索算法能使得当前的模型在实际游玩中提升胜率多少。第二目标，确定加入搜索，或者通过搜索蒸馏。是否对训练有益。充分保留数据……测试规模中等，我希望能在一个小时的时间窗口内结束。”测试中途：“允许你的测试窗口增加1个小时。……如果方向明显不对，不要硬来。”同时问了局外决策的搜索有没有希望。决策记录 217。

停训窗口：本机时间 14:26–16:07（B 机时间 21:26–23:07），约 1 小时 41 分钟。B 停在第 124,744 版（备份 v124744-20261031-2126-搜索测试前），16:07 恢复，第 124,747 版起每秒约 10,800 决策。被测模型：第 122,056 版（千种子复测 60.6%，复测留存的权重）。

## 结论

1. **搜索在实际对局里明显有用。** 只在第三幕两个 Boss 上用搜索，连打两个 Boss 的胜率从 67.0% 升到 73.7%，**+6.7 ± 1.7 个百分点**（475 题逐题配对；只有搜索赢 51 题，只有贪心赢 19 题，p = 0.0002）。换算到整局约 **+5.7 ± 1.5 个百分点**：千种子复测 60.6% → 约 66%（95% 区间约 63–69%）。第 108,583 版上的第 0 步诊断是 +7.4 ± 2.9，训练又过了约 1.4 万次更新，收益没有明显缩水。
2. **这次的离线蒸馏没有用，整局还变差。** 用 38,313 条搜索标签各微调一份（soft、hard 两种目标）：留出的 1,574 道双 Boss 题上，soft −1.0（p = 0.22），hard +0.5（p = 0.60）；soft 在 384 个种子的整局上 54.4% 对原模型 59.1%，**−4.7 个百分点**（p = 0.11）。微调后，搜索改选过的决策只有 5–6% 学到了搜索的选择，搜索确认过的决策反倒有 11–14% 被改掉。也就是说，网络没学到搜索的改进，只是被扰动了。
3. **局外选牌的搜索看不到信号。** 193 个第一、二幕的选牌决策、349 个有随机性的替代选项：显著好于网络选择的 17 个（4.9%，纯噪声预期约 4%），显著更差的 129 个（37%）。推演找不到比网络更好的选牌，反倒大量确认网络的选择。
4. **对训练的含义**（推断）：
   - 搜索的收益是真实的，但按这次的离线做法蒸馏不进网络。搜索要惠及直播，最直接的是在直播里跑搜索，也就是另一个会话在做的直播公开信息树搜索（决策记录 214–216）。
   - 把搜索放进训练的采集，C# 重放后端太慢：两台机器 95 分钟只做完 475 场双 Boss 战，训练一小时打二十多万场 Boss 战（每版约 190 场、约 3 秒一版），搜索只能覆盖千分之一。要做，得等能复制状态的 Rust 引擎。
   - 局外决策的搜索，用这种推演方式不值得投入。

## 一、第一目标：实际对局里多赢多少

**做法**：题取自第 122,056 版千种子复测里整局打到第三幕第一个 Boss、并记下了开打前快照的全部 526 局。按随机顺序编号，不分层抽样，保持实际对局的分布；复测里另外 362 局沿用了评测结果，没有快照。每题从快照连打两个 Boss，贪心和搜索用同一个种子逐题配对。搜索沿用第 0 步诊断的设置：
- 网络最想选的项概率不到 0.9 时，取概率前 4 的候选（各至少 2%）；
- 共同随机数，逐轮减半 2 轮，首轮每候选 4 次推演；
- 推演 12 步后用战斗价值头估值；
- 与贪心项逐世界配对，平均差超过 2 个标准误才改选。

推演前一律重洗随机数和抽牌堆，价值头不给特权输入，所以搜索不读真实种子，属于公开信息搜索。

**快照能代表实际对局**：同一批 526 题，从快照贪心重打 67.1%，复测整局里这些局实际的条件通关率 69.8%。

**结果**（475 / 526 题做完，其余 51 题是截止时 A 上还没开打的，按随机顺序排在后面）：

| | 贪心 | 搜索 |
|---|---|---|
| 两场都赢 | 318（66.9%） | 350（73.7%） |
| 打到第二场 | 424 | 442 |
| 两边都打到第二场的 421 题里，第二场赢 | 317 | 343 |

| 第一个 Boss | 题数 | 贪心 | 搜索 |
|---|---|---|---|
| 永世沙漏 | 165 | 105 | 114 |
| 女王 | 148 | 101 | 108 |
| 实验体 | 162 | 112 | 128 |

两场 Boss 战上都有收益：打到第二场的多了 18 题，第二场的胜率也高了约 6 个百分点。三种 Boss 开局都有收益，实验体开局的最多。

**换算到整局**：到达第三幕第一个 Boss 的比例 84.7%（复测）× 条件胜率差 6.74 个百分点 ≈ +5.7 ± 1.5 个百分点。前提是第三幕之前完全按贪心打，与复测相同。

**代价**：每题平均 120.7 个决策，其中 80.7 个搜索、9.4 个改选（11.6%），2,234 次推演。两台机器 95 分钟做完 475 题；一场双 Boss 战的搜索约要两台机器 12 秒的全部算力（C# 重放后端，每次推演都从战斗开头重放）。

## 二、第二目标：蒸馏对训练有没有用

**做法**：
- **标签**：搜索过的每个决策一条，共 38,313 条，含原始观测、网络概率、各候选的推演得分，其中 4,461 条改选了。按题留出十分之一，共 3,518 条。
- **soft 目标**：π′(a) ∝ π(a)·exp((Q̂(a) − Q̂(贪心))/0.1)。
- **hard 目标**：搜索的选择，另加 0.5 × KL(π 原 ‖ π 新) 拴住原策略。
- **训练**：学习率 2e-5，2 遍，544 次更新，每条标签按战斗练习和整局两种模式各训一次，只训策略输出。
- **评测**：留出题取自另外三个版本（第 120,174、118,319、116,396 版）复测的全部第三幕 Boss 快照，共 1,574 题，贪心逐题配对；整局为 RT0000–0383，与第 122,056 版千种子复测的同种子结果配对。

| | soft | hard |
|---|---|---|
| 留出标签：搜索改选过的决策里学到搜索选择的比例（微调前 0%） | 6.4% | 6.2% |
| 留出标签：搜索确认过的决策里保持原选择的比例（微调前 99.3%） | 85.8% | 88.3% |
| 与原策略的平均 KL | 0.018 | 0.040 |
| 留出双 Boss 题，两场都赢（原模型 1,044 / 1,574） | 1,028（−1.0，p = 0.22） | 1,052（+0.5，p = 0.60） |
| 整局 384 个种子（原模型 227） | 209（−4.7，p = 0.11） | 没测 |

整局只测了 soft：它是事先定好的主方案，时间只够测一份。

**解读**（推断）：
- 改选只占一成，而且多数是 Q 差很小的出牌顺序调整，标签信号弱。
- 两遍小学习率的微调学不进这些改选，却在别处引入了扰动。soft 目标在没有显著差别的候选之间也挪了概率。
- 用战斗口径的标签同时训整局模式，可能也伤了整局里的其他决策，整局 −4.7 就是这个方向的迹象，但不显著。
- 这次的结果不能证明蒸馏原理上不行，只能说明这种低成本的离线做法不行。要再试，得换成只在改选决策上加权、目标更保守、混进 PPO 一起训的做法，并且要比这次多一个数量级的标签。
- 按决策记录 214，带种子搜索的结果不能进策略、不能当蒸馏目标。本次搜索不读真实种子，所以蒸馏试验本身不违反它；以后要不要把公开信息搜索的结果用于训练，由用户定。

**搜索放进训练采集的代价**：按这次的速度，两台机器每小时约 300 场双 Boss 战的搜索，训练每小时打二十多万场 Boss 战（含连打练习），只能覆盖约 0.1%。C# 重放后端不适合放进训练。

## 三、局外选牌的搜索信号探针

**做法**（tools/meta_probe.py）：
- 整局模式贪心打 24 个种子（PX0000–0023），在第一、二幕网络最大概率 < 0.9 的选牌决策上，取前 3 个候选。
- 每个候选在 8 个重洗世界里，从整局开头重放到这里、走这个候选，之后贪心打到进下一幕或死亡。
- 得分：死亡时 0.02 × 多走的层数；进下一幕时 0.02 × 层差 + 0.5 + 局外价值头在下一幕第一个决策上的估值。
- 重洗只换战斗相关的随机数（洗牌、怪物出招等），以后的卡牌奖励、商店、变化用的是真实那一份。所以推演看得到未来的奖励，结果只能用于分析。

**结果**：

| | 数量 |
|---|---|
| 选牌决策（第一幕 / 第二幕） | 193（106 / 87） |
| 替代选项：有随机性 / Boss 后选牌（推演里没有随机事件） | 349 / 32 |
| 有随机性的替代：显著更好（差 > 2 个标准误） | 17（4.9%；零假设约 4%） |
| 有随机性的替代：显著更差 | 129（37.0%） |
| 差的中位 / 均值；标准误中位 | −0.086 / −0.144；0.107 |
| Boss 后选牌：替代项估值更高 | 2 / 32 |

显著更好的比例和噪声持平，网络的选牌在这种推演下几乎找不到改进空间。限制：只看了选牌、只推演到本幕结束、叶子是局外价值头。选路、商店、事件没测；“只推到本幕结束”也看不到牌组对第三幕 Boss 的长期影响，这正是决策记录 125 的选牌前瞻没做好的地方。

## 四、过程与数据

- **流程**：
  - 14:26 停训，两台各 12 个分片做第一段，14:50 截止。
  - A 的瓶颈在每个分片的 Python 进程（单核约 90%），第一段速度只有 B 的四分之一。
  - 14:57 起第二段，A 改成 24 个分片 × 2 个引擎，剩下的题 B 拿三分之二，15:45 截止，15:57 强停。
  - 之后蒸馏、留出题、整局评测，16:07 恢复训练。
- **偏差**：
  - 做完的题是两段各自随机顺序的前一段，截止时手上的题都做完了（只有 15:57 强停的 16 个分片丢了在做的题），没有明显偏向。
  - 做完的 475 题贪心胜率 66.9%，全卷 67.1%。
- **数据**：本机 `~/.local/share/sls2/search_test/20261031-1426/`（1.3 GB，含全部标签、两份蒸馏检查点、逐题结果、探针记录、整局记录、日志），两台的 `/root/sls2-search/out/20261031-1426/` 各留原件。
- **汇总**：goal1.json、hold_soft_vs_orig.json、hold_hard_vs_orig.json、full_soft_vs_v122056.json。
- **工具**：
  - `tools/search_test.py`：建题、带标签的搜索、蒸馏、合成、整局配对。
  - `tools/meta_probe.py`：局外选牌探针。
  - `tools/remote/search_window.sh`、`search_window2.sh`、`search_window3.sh`：窗口的停训、分工、收尾、恢复。
  - 搜索核心沿用 `tools/mcts_eval.py` 与 `tools/search_diag.py`。
