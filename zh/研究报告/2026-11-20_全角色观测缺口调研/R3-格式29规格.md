# R3-格式29规格：六个角色统一观测格式 29 的实现规格

2026-11-20，第三轮 R3-规格。只读代码，只写本文件。

**依据**：R2-汇总（G01–G63）、R2-角色遗物、R2-编码、核实 6 与第一轮 9 份报告。游戏源码路径相对 `~/.local/share/sls2/decompiled/v0.113.1/`，省略前缀 `MegaCrit.Sts2.Core.`；引擎路径里的 `Obs/` 即 `engine/Sts2Headless/Engine/Obs/`。源码行号沿用各报告，本轮补查过的另注。

**基线**：主会话已提交格式 29 的骨架 bd2d102：`Format.cs` 的 `FormatAll = 29`、`V29`、`TokFeats29 = 30`、`CandFeats29 = 20`；`Observation._y`（记录新列 22–29）、`_cy`（候选新列 14–19，每个候选开头清零），V29 时由 `Emit` 与 `AddChoices` 写出；Python 端 `feat_v29` 按记录类型 0–15 分块、`cand_v29` 按战斗内外分两块，都清零初始化。本规格按这个骨架写。

## 摘要

- 共 87 条：G01–G63 来自 R2-汇总；G64–G75 是 R2-角色遗物第一节的 12 条；G76–G87 是 R2-角色遗物第四节、R2-汇总第四节“没人查”、R2-编码第六节的线索。
- **做 66 条，不做 21 条。** 做的里面有 4 条（G52、G53、G54、G58）是格式 29 已经包含的门控，不用写代码；有 15 条只做一部分，范围写在第二节。
- 新列：记录用了 6 类（生物 22–29、招式 22–24、能力 22、遗物 22、全局 22–23、选项 22）；候选战斗内用 14–17、战斗外用 14–17，两块各留 18–19。没有新的记录类型。
- 一个第 0 步（主会话，分包之前加接口与桩）加 **5 个实现包**：回合预演、背包、候选与增益、角色与附带效果、生物与局外。
- “需要核实”的 13 条：11 条读代码定了，2 条（第 7、13 条的一部分）给了保守做法。

## 一、总则

### 1.1 写法约定（各包都遵守）

1. **一切改动只在 `V29` 下生效。** 格式 19–28 的每一帧必须与改动前逐字节相同（`tools/engine_equal.py` 核对）。
2. **改算法时，优先新写一个 `Xxx29` 函数，V29 下改调新函数，旧函数原样留着。** 只有一两处分支的小改动才直接在原函数里加 `if (V29)`。
3. **新函数写在本包名下的文件里，或本包新建的文件里**（`Observation` 是 partial class，建议文件名以 `29` 结尾，如 `Obs/Knap29.cs`）。可以调用别包文件里的函数，但不改别包的文件。别包函数在 V29 下的行为会变（例如 `ExhaustOthers` 会认浩劫），一律以合并后的结果为准。
4. **新列的写法**：记录新列在 `Begin()` 之后、`Emit()` 之前写 `_y[i]`（列号 = 22 + i）；候选新列写 `_cy[i]`（列号 = 14 + i）。第三节的表给每一列指定唯一的写入包，别的包不写。
5. **写原值**：张数、生命、伤害、0/1。Python 端统一做符号对数压缩（先截到 ±1e4）。不往新列写词表 ID。需要比较的量由引擎算好结论（同 R2-编码第五节的约定）。
6. **出错退回旧值**：新分支包在 try/catch 里，异常时走原来的算法。调过 `Preview(card, target)` 的照现有写法用 `Preview(card, null)` 复原；临时改游戏对象时用 `MemoPause/MemoResume`。
7. **耗时**：`tools/engine_bench.py` 量铁甲整局帧的编码耗时，全部合并后增加不超过 20%。

### 1.2 列号在 Python 端怎么分组（决定了下面的分配）

- `feat_v29` 按 TokenKind 0–15 各占一块（`python/sts2rl/model.py` 的 `V29_KINDS = 16`）。同一类型里一列只能有一种含义。生物（类型 2）的敌人、玩家、宠物共用一块，所以**敌人用 22–27，玩家用 28–29，互不重叠**，宠物（奥斯提、瓦皮等）全为 0。
- 战斗计数（类型 15）各子类型共用一块，本次**不在战斗计数上开新列**。
- 类型 ≥ 16 的记录不进 `feat_v29`，本次不用。
- `cand_v29` 按这一步是不是局外决策（`features.macro_rows`：不在战斗中，且不是战斗、结束、卡住）分两块。战斗内的各种候选（出牌、药水、结束回合、选牌）共用一块，所以战斗内每一列的含义要对所有候选成立，不适用的候选写 0。

### 1.3 现有列的空位

按框架，现有列里恒为 0 的空位一概不填。本规格里所有“改值”都是**同一列、同一含义下把算错的值改对**（例如药水候选的 4–7 与出牌候选同义），不借空位放新含义。会改到老列的条目在第三节 3.3 列清楚，`tools/obs_v29_check.py` 据此登记“允许不同”的位置。

### 5.1 包 1：回合预演（`Obs/EndTurn.cs`）

**统一结算函数。** V29 下把 `Loss` 与 `Loss22` 合成一个按攻击者逐段结算的 `Loss29`（参数同 `Loss22`：`atks` 带攻击者、`tough`、`ex`、`ostyEx`、`handEx`、`gone`、`skip`、`fx`），`res[me]`、`worstLoss`、`after`（`LossAfterFn`）在 V29 下一律走它；格式 ≤ 28 仍走原来两条路径。`Loss29` 的结算顺序（每一步对应下面的条目）：

1. `pre`（`handEx`，这一步当场挨的伤害）——玩家一侧；
2. `handSeq`：跳过 `gone`、`fx.Gone`、`fx.Played` 对应的牌；`HandAdj` 照旧——玩家一侧；
3. 加上吞噬暗影激发的冰霜格挡（照旧）；
4. `lateSeq`：跳过施加者在 `fx.Dead` 里的项（G27）——玩家一侧；
5. 玩家的灾厄（G36）：`hp − 已掉 ≤ 灾厄层数` 就返回当前生命；
6. 敌人的攻击，逐个攻击者、逐段：瓦皮先挨 → 无实体压到 1 → 格挡（倒映，G51）→ 奥斯提 → 钨棒 → 缓冲 → THE_GAMBIT（G32）→ 律动残余（G03）→ 纸片割伤计数（G28）→ 荆棘、亡灵精通扣攻击者的 `left`（荆棘含 `fx.Thorns`，G50/G72），攻击者 `left ≤ 0` 后剩下的段不打；
7. `postSeq`：律动残余的额度重新从 20 起算。

“玩家一侧”的每一次掉血按序过：无实体、格挡（可格挡的）、钨棒、缓冲、恶魔之舌（G32）、律动残余（G03）。
