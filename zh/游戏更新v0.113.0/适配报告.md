# 游戏 v0.113.0 适配报告（2026-11-12）

用户 2026-11-12 晚：“今晚每隔 20 分钟检查一次《杀戮尖塔》有没有新的更新出来。如果出来了，你把新版本下载下来，检查一下新旧版本有什么不同，再看一下我们的观测格式如何适应新的版本，然后在一个独立的分支里建立新版本的 PPO 训练全流程。”

21:06 的检查发现 Steam public-beta 分支出了新版本 **v0.113.0**。这份报告记录拿到新版本、比较新旧差别、适配引擎与观测、搭训练管线的全过程。所有改动在分支 `game-v0.113.0` 上（工作目录 `~/dev/sls2-v0.113.0`，从 master 的 83169d9 分出），没有合进 master，也没有部署到租用机。

同目录的附件：
- `Fool调研.md`：新角色 Fool 的机制、状态字段与观测建议（子代理调研）；
- `老内容改动调研.md`：Fool 以外老内容的改动、对引擎与训练的影响（子代理调研）；
- `影响评估.md`：`tools/game_update/update_impact.py` 的输出。

- **训练管线**：
  - 发现并修了一个严重隐患：换游戏版本时内容先验的特征列整体错位，而且不报错；
  - 猎人第 26,428 版在 v0.113.0 上续训冒烟通过；
  - Fool 从零开训的配置、部署和启停脚本已备好，本机冒烟通过。
- **要你定的**：
  - 直播用的游戏已被 Steam 标成“需要更新”，要防自动更新；
  - 什么时候在 B 上把训练切到 v0.113.0、练哪个角色；
  - 非 Fool 角色的训练要不要去掉 Fool 解锁。

## 二、新旧版本有什么不同

### 2.1 新角色 Fool（详见 `Fool调研.md`）

- 能在标准单人模式选（正式游戏要先用故障机器人打完一局解锁；无头全解锁，直接传 `"FOOL"` 就能开局）。77 生命、99 金币、3 能量、1 个箭位、没有充能球位。
  初始牌组：打击 ×5、防御 ×4、愚者射击；初始遗物：歌曲之弓（每场战斗开始 6 瞄准）。
- **箭矢**：箭没有种类，每支箭是一个箭位，状态只有在手上、扎在敌人身上、已摧毁三种。射击牌（标签 `Shoot`，12 张）射出最后一支可用的箭：
  - 先结算这张牌的伤害（新的伤害标志 `FromArrow`），再让目标获得“扎穿”；
  - 之后对它每打中一段有力攻击，扎穿计数减 1，到 0 拔出最早的一支箭；
  - 目标死亡或逃跑时，箭全部回来；
  - **没有可用的箭时，射击牌照样打出、照样花能量，但攻击完全不执行**；
  - 箭位只有箭袋能加，没有上限。
- **旋律**：本回合打出过带哇、啾、叽标签的牌，就拥有这种旋律。没有专门字段，按战斗历史现算。很多牌按旋律种类数加段数、减费、抽牌。
- **塔罗**：22 张 0 费消耗的衍生牌，只由“神话形态”每回合随机加入手牌，会带来别的角色的机制（充能球、小刀、灾厄、额外回合、别的角色的牌）。
- 其他：悲伤与喜悦、拉伸（格挡版瞄准）、额外回合、免费出牌、弹跳回手、自动打出抽牌堆顶（失落鲁特琴、恶魔）、召回（放到抽牌堆顶）。

### 2.2 老内容（详见 `老内容改动调研.md` 第〇节）

- **标准单人 A10 的规则大体没变**：进阶定义、四幕遭遇池、Boss 都没变。新增 5 个事件、8 件非 Fool 遗物、4 张事件卡、1 张无色卡、2 个休息处选项（异鸟进化、瓦皮恢复）；休息处最低可出现的行从 6 降到 5。
- **已训练角色**：
  - 猎人：铭记死亡重做（3 费、奇巧、打当前生命最低的敌人）；独门技术改为整手保留；幻影之刃 9(12) → 8(11)，小刀的“保留”改成动态关键词；速行者 2 → 3；
  - 储君：仆从俯冲 13(16) → 11(13)；
  - 故障机器人：螺旋钻击修了段数计算，喧哗换了随机流。
- **多段攻击**：21 张牌改用新的 `HitCountVar`。
- **怪物**：
  - 巨斧机器人 HP 固定为 80；
  - 感染棱柱删掉“辐射”，“脉动”从自己 22 格挡改成给玩家 1 层易伤；
  - 火箭、地道虫的招式改名（地道虫 A10 伤害 26 → 28）。
  - 引擎写死的 Boss 招式表（MoveGains）10 项全部仍然有效。
- **随机数**：
  - 洗牌改成先从父流派生子 `Rng` 再洗；
  - 新增玩家随机流 `NonCombatGeneration`；
  - 商店不再消耗 `Rewards` 流；
  - 约 20 个消费者换了随机流。
  - 所以**同一种子在两版下的地图、商店、洗牌全都不同**。
- **规则层**：
  - 伤害结算在格挡前多了一步“转移目标”（瓦皮替玩家挨打）；
  - 玩家身上的减益只在敌方回合施加时才跳过下一次减层（更新说明没写）；
  - 选牌器从全局栈改成每局每个玩家一个栈。
- **Blitz、Dread** 只在对应模式生效。无头固定用标准模式，不会误触发。

## 五、观测格式如何适应新版本

### 5.1 老角色（db6c272、be7f478 及 d24c289 里的一处）

| 改动 | 原因 | 对帧的影响 |
|---|---|---|
| 佩尔之眼的额外回合判断 | 见第三节第 2 条 | 只在有佩尔之眼、本回合没出牌时 |
| 段数读新的 `HitCount`（所有格式） | 21 张旧牌改用它：12 张原来是 `Repeat`，所有格式都读，比如猎人的弹射、储君的七星、故障机器人的黏液弹；不读就退成 1 段 | 这 12 张保持原来的段数。故障机器人（格式 19）的喧哗、撕裂、双重打击从原来少算的 1 段变成正确的 2 段，帧会变，方向是改对 |
| XHits 不再把 8 张两段攻击写死成 2 段；X 费攻击的段数也过 `Hook.ModifyAttackHitCount` | 新遗物拇指夹给多段攻击 +1 段，写死会把这一段盖掉 | 没有拇指夹时结果不变（两版里只有拇指夹实现这个钩子） |
| 铭记死亡按当前生命最低的可攻击敌人算候选 4–7 | 新版的铭记死亡标着打随机敌人，实际目标是确定的 | 猎人有铭记死亡、敌人 ≥ 2 时。200 场核对：打死预测 628/628 一致；没打死时伤害预测 361/369，不一致的 8 次全是滑溜，候选 6 记的是伤害、不是掉血，与所有单体攻击同一口径 |
| 手牌外的小刀在有幻影之刃时也记保留 | 新版改成动态关键词后，只看本地关键词就丢了 | 恢复 v0.111.0 的口径（猎人模型学的是这个） |
| 黑曜石钳子算进回合结束预演 | 新遗物：回合结束前对随机敌人造成“手牌张数”点无力伤害 | 只在有这件遗物时 |
| 7 条别名 | 见第四节 | 改了名的招式、龙涎香仍用老 ID |

对拍：加完 be7f478 的五处修正前后，六个角色 46 局 × 6 共 9,085 帧，只有猎人 5 帧不同。逐项解出来全是预期的：3 帧是铭记死亡的候选，2 帧是弃牌堆小刀的保留位。

**同一个检查点在新版本下看到的帧，和在 v0.111.0 下本来就不同**：游戏内容、随机数、数值都变了，这在意料之中。上面这些改动的目标是让“同一件事”的编码口径不变。

### 5.2 Fool：观测格式 24（7b92b9c，`观测格式.md` 四之六）

以格式 23 为底（已知牌堆顶、能力内部数据、遗物本回合已触发、格式 21/23 的候选与预演口径、荆棘反伤），加格式 22 的灾厄 12–13（塔罗“死亡”给 75 灾厄），再加 Fool 专属：

- **战斗计数子类型 4**：
  - 箭：箭位总数、可用、扎着、摧毁；本回合、本场射出的箭；
  - 旋律：本回合哇、啾、叽三个位，旋律种类数，本回合旋律牌张数；
  - 本场生成的悲伤张数。
- **扎穿能力记录 12–13**：扎着几支箭；全部拔出还要打几段。
- **射击牌门控**：没有可用的箭时伤害预览为 0；钉住对没被扎穿的目标为 0。
- **弹跳**：同流星锤，记下回合回手。
- **已知牌堆顶**：现有补丁直接能跟踪“召回”，格式 ≥ 20 时自动启用。这一项照用户的长期备忘提出：做其他角色时主动考虑已知牌堆顶。

布局不变，网络不用改（`n_zones` 19）。核对：
- 加格式 24 前后，其余五个角色 46 局 7,839 帧逐字节相同；
- 200 场 Fool 专门牌组、5,734 个战斗帧，七项检查全部一致：箭位守恒、扎着的箭与扎穿记录一致、没箭时射击牌预览为 0、打出射击牌后射出数正确、没箭时打射击牌目标血量不变（op state 对照，803 次）、旋律位等；
- Fool 随机整局 20 局 1,504 帧全为格式 24，卡住 0。

### 5.3 没做的（列为后续）

## 六、训练管线

### 6.1 内容先验的列错位：发现与修复（bb3d5af）

**问题**：内容先验（每个词表 ID 一行静态属性，经清零初始化的线性映射加到记录上）的特征名，是把整个内容目录的特征按字母排序得到的（`content.py:112`）。新版目录多了新类别、卡池、效果签名，新名字插在中间：v0.111.0 是 1,072 列，v0.113.0 是 1,195 列，原来的位置上同名的只剩前 7 列。载入检查点时 `load_state` 只会在末尾补 0 列（为附魔、升级两组追加列写的），Adam 的矩也是。结果老检查点的映射整体错位，**不报错，训练照样能跑**。我先按旧代码跑过一次冒烟，同样出了两版、毫无异常，所以这个问题只靠“能跑”是查不出来的。

**量化**（第 26,428 版猎人滑动平均权重）：两版特征完全相同的 1,544 个词表条目，内容先验的投影在旧办法下平均偏差 1.66、最大 22.6，而投影本身的平均幅度只有 1.47，等于打乱。

**修复**：
- 按特征名对齐：同名的列原样搬，新特征补 0，旧版独有的丢掉；
- 检查点新存 `content_names` 与 `catalog_version`；旧检查点没记特征名的，按列数在 v0.111.0、v0.107.1 的内容目录里把当时的特征名算回来；
- 续训时权重、Adam 的一二阶矩、Muon 动量、滑动平均都按名字对齐。
- 修复后，特征没变的 1,544 个条目投影最大差 3.8e-6（浮点舍入）。

这个隐患不只影响这次升级：以后每次游戏更新只要内容目录多了特征，都会触发。上次 v0.107.1 → v0.111.0 升级时有没有受影响没查（那时的内容目录特征变化可能小一些）。

### 6.2 老角色在新版本上续训

本机冒烟（1 个采集进程、4 个引擎、每版 2,048 步，CPU）：第 26,428 版猎人滑动平均权重在 v0.113.0 上续训，日志依次出现：
- “内容先验按特征名对齐：1072 列 → 1195 列，对上 1071 列”；
- “词表 2286 → 2557 项：新增 ID 的嵌入行已清零”。

出了第 26,429、26,430 版，没有报错；存下的检查点带上了特征名。

**涅奥开局的遗物选项（2026-11-13 补）**：
- **问题**：
  - 这 30 个选项键（`EVENTOPT:NEOW.pages.INITIAL.options.<遗物>`）在 v0.111.0 及以前不在词表里，老模型看到的一直是 `<unk>`；遗物本身在附加 ID 里。
  - 这次适配把它们追加进词表（第 2,527–2,556 号）。续训时新 ID 的行按惯例清零，老模型在涅奥那一帧看到的输入就变了。
  - 这是词表的变化，`STS2_OBS_NO_FIX113=1` 退不回去。
- **处理**（`model.zero_new_vocab`，前缀表 `WAS_UNK_PREFIXES`）：
  - 新 ID 里旧版就有、当时记 `<unk>` 的，不清零，改取 `<unk>` 那一行。老模型的输入与旧版逐位相同，续训时这些行再各自学开。
  - 续训时滑动平均权重同样处理。原来只清了当前参数，滑动平均里新 ID 的行一直是建网时的随机值，要约 1,000 版才衰减掉。
  - `play_live.py` 调的也是这个函数，调用方式不变。
  - 检查点词表已是新的（愚者，`vocab_n` 2,557）时，这一步不会执行。
- **核对**（猎人第 26,428 版滑动平均权重，v0.113.0 引擎，12 个种子的涅奥帧，共 36 个选项记录）：
  - 新办法与“把这 30 个 ID 换回 `<unk>` 的同一帧”打分、估值逐位相同。
  - 原办法（全部清零）有 6/12 帧首选变了：打分最大差 14.6，估值最大差 0.42，策略分布总变差平均 0.39、最大 0.92。
  - 其余新 ID 的行仍为 0，旧行与检查点相同。
- 别的新 ID 都是新内容，旧版里没有，清零是对的。非涅奥古神的遗物选项等几类，新版仍记 `<unk>`（观测独立核查第九节），对老模型没有变化。

在 B 上切到新版本的步骤（还没做，等你定）：
1. 把分支部署到一个新目录，编引擎。租用机上没有 v0.113.0 游戏文件时，照 `tools/remote/fool/deploy.sh` 的做法先同步过去，约 100 MB。

4. 巡检的基线与报警线重取：同种子跨版本不可比；评测种子池照用，但数字以切换为界不能直接比，看板要加口径分界线（同决策记录第 70 条的做法）。

## 七、风险与要你定的事

1. **直播用的游戏会被自动更新**：
   - Windows Steam 里这个游戏的自动更新是“高优先级”，分支 public-beta；21:47 已被标成“需要更新”（`StateFlags` 6），游戏还开着、还是 v0.111.0；
   - 直播守护进程从 Steam 重开游戏时，Steam 很可能先更新，桥接模组对新版编译不过（第 5.3 节），直播会断；
   - 要不要防、怎么防，由你或直播会话定（Steam 设置与直播文件我没动）。
2. **训练什么时候切到 v0.113.0、练哪个角色**：
   - 猎人在 v0.111.0 上第 28,572 版又报了练习走平，第 26 条的集成测试也显示滑动平均不再变强；
   - 可选：在 v0.113.0 上续训猎人（按第 6.2 节），或在 B 上从零开训 Fool（按第 6.3 节），或两者都做（B 的显存放不下两条训练线同时跑，要排先后）。
3. **非 Fool 角色要不要去掉 Fool 解锁**：
   - 无头用全解锁，Fool 算已解锁。没解锁 Fool 的实机账号有三点不同：跨角色效果抽不到 Fool 的牌、多彩哲学家没有 FOOL 选项、涅奥不出万花筒（它要求 6 个角色全解锁）；
   - 直播账号如果已经解锁 Fool，就不用管。
4. **v0.113.0 只在 beta 分支**，正式分支仍是 v0.111.0 的内容；beta 之后可能改动或撤回。
5. **sts2-sim、Rust 引擎**停在 v0.111.0，第三幕搜索暂不能用于新版本。
