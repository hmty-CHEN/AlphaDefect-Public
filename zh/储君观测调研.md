# 储君（The Regent）观测调研（2026-11-06）

用户：“暂时把故障机器人的收一收，我们试试看去做储君模型，到时候从零开始训练，一样的架构，你可以先调研有关储君有哪些新的观测需要做了。”

依据：反编译的游戏源码 v0.111.0（~/.local/share/sls2/decompiled/v0.111.0）与当前观测编码器 `engine/Sts2Headless/Engine/Observation.cs`（FormatVersion 19）逐项对照。只读调研，没有改代码。

## 一、储君的专属机制

- **星（第二种资源）**：`PlayerCombatState.Stars`，每场战斗从 0 起（起始遗物神授之权 DivineRight 进房间时给星）。卡牌除能量费外还有星费：`CanonicalStarCost`、`CurrentStarCost`（含临时星费）、出牌时按 `GetStarCostWithModifiers()` 判断够不够（不够为 `StarCostTooHigh`）；星尘（Stardust）是“星 X 费”（`HasStarCostX`）。有钩子 `ShouldPayExcessEnergyCostWithStars`（能量不够时可用星补）、`TryModifyStarCost`（虚空形态把前几张牌的星费改成 0）。
- **锻造（ForgeCmd）**：本场第一次锻造时往手里生成君王之剑（SovereignBlade，2 费攻击、保留），之后每次锻造给所有未消耗的君王之剑加伤害。君王之剑的伤害与段数在通用数值 Damage、Repeat 上；有寻锋（SeekingEdgePower）时目标变成全体敌人，有招架（ParryPower）时打出还给格挡（CalculatedBlock）。11 张卡与 1 种药水（王者之勇 KingsCourage）会锻造。
- 91 张专属卡（25 张带星费），专属能力约 25 种，专属遗物 8 个，专属药水 3 种（星之药水、宇宙调和、王者之勇，目标都是玩家自己）。
- 词表（engine/catalog/vocab.txt）已经有储君的卡、角色与药水（CHARACTER.REGENT、CARD.SOVEREIGN_BLADE 等），不用加词。

## 二、现有观测已覆盖、不用改的

- 当前星数：全局特征 8。
- 君王之剑的成长：伤害、段数都在 DynamicVar（Damage、Repeat）上，卡牌特征 5、16（伤害、预览伤害）和 7–8（其他数值）能看到；寻锋改变的目标类型由引擎按游戏的 `CanPlayTargeting` 生成候选，自动对。
- 伤害随局面变化的卡：王者之拳（每抽一次加伤害，写在 Damage 上）、超大质量（Supermassive）与新月之矛（CrescentSpear）（CalculatedDamage）、辐射（Radiate）与月之冲击（LunarBlast）（CalculatedHits），手牌按界面预览编码。
- 能力：层数、界面显示的数、前两个 DynamicVar、本回合 / 本场已触发（按属性名）、在能力列表里的顺序。轨道（OrbitPower，界面数 = 再花几点能量触发）、独白（MonologuePower，界面数 = 已加的力量）的关键状态都在界面数里。
- 遗物计数：银河尘埃（GalacticDust）的已花星数是 DisplayAmount，已编码。
- 选牌：从手牌、战斗牌堆、三选一界面选牌都是现有的选牌决策；抽牌堆选牌（家庭教师 Tutor、冲锋 Charge）游戏会先按稀有度、卡牌 ID 排序再给选牌器，不泄露整体顺序（同 ID 副本的问题见下）。
- 以玩家为目标的卡（Tutor、慷慨 Largesse，目标类型 AnyAlly）：游戏在单人局里判为不能打出，引擎用的是游戏的判断，不用处理。

## 三、需要改的观测（按优先级）

### 优先级 1：直接影响储君核心打法

1. **已知的抽牌堆顶**（记忆条目、决策记录 129、后续计划.md：做其他角色时要主动提出）。
   现在抽牌堆按卡牌编号排序输出，模型看不到玩家其实知道位置的牌。储君有 4 张专属卡会把牌放到抽牌堆顶：闪耀打击（ShiningStrike，打出后回到抽牌堆顶，`GetResultLocationForCardPlay`）、闪光（Glimmer）、光子切割（PhotonCut，抽牌后选手牌放回顶部）、宇宙冷漠（CosmicIndifference，从弃牌堆选一张放到顶部）。
   另外“我无敌”（IAmInvincible）在回合末恰好位于抽牌堆顶时会自动打出（`AfterAutoPostPlayPhaseEntered`），配合闪光、光子切割主动把它放上去，是一条明确的打法；看不到牌堆顶，模型学不会。
   拟定做法（同决策记录 129）：引擎记下在玩家眼前被放到抽牌堆顶的牌（`CardPile.MoveToTopInternal` / 插到下标 0），被抽走或抽牌堆重洗后失效；这几张牌单独输出到“抽牌堆第 1、2、3 张”的新区域（不进汇总槽平均）。
2. **手牌的星费用带修正的值，加“星 X 费”标记**。
   卡牌特征 2 现在是 `CurrentStarCost`（不经钩子）；能量费（特征 0）对手牌已用 `GetWithModifiers(CostModifiers.All)`。虚空形态（VoidFormPower）让每回合前几张牌的能量费和星费都变 0：能量费会显示 0，星费仍显示原价，两者不一致。改为手牌用 `GetStarCostWithModifiers()`；新增一项标记 `HasStarCostX`（特征 1 只标能量 X 费）。
3. **X 费卡的预览段数**。
   `Preview` 只认 Repeat 与 CalculatedHits 两种段数。星尘（Stardust，每颗星打一段）、天穹钻头（HeavenlyDrill，能量 X 段，够阈值时翻倍）的段数会被当成 1，候选特征 4–7（单次伤害、段数、总伤害、能否打死）与 10（回合结束掉血）都会算错。按 `ResolveStarXValue` / 当前能量补上这两种的段数。

### 优先级 2：少见但会影响合法性或时机判断

4. **遗物的“本回合已触发”**：遗物特征 6 只读名字以 `ThisCombat` 结尾的字段；小储君（MiniRegent）与君王石（Regalite）用的是 `_usedThisTurn`（每回合第一次花星 / 生成牌时触发），现在编不进去。加一项“本回合已触发”（字段名以 `ThisTurn` 结尾），或并入特征 6。
5. **能力内部数据**：`PowerUsed` 只读能力类自己声明的属性，读不到 `InitInternalData` 里的数据。
   - 虚空形态：本回合已打了几张牌（`cardsPlayedThisTurn`），决定还剩几张免费牌。补一项“还剩几张免费”。
   - 暗淡蓝点（PaleBlueDot）：`alreadyActivatedThisTurn`。多数情况下界面数为 0 时就是已触发，可以不补，但补上更稳。
6. **抽牌堆选牌候选的同 ID 副本先后**（通用问题，不只储君）：游戏按稀有度、卡牌 ID 做稳定排序，同 ID 的几张牌（升级、附魔不同）在候选里的先后沿用它们在抽牌堆里的真实顺序，会漏出哪一张更靠上。编码候选时同 ID 再按升级次数、附魔排序（或固定打乱），去掉这点泄漏。

### 优先级 3：可推出来，加了能省模型的力气

7. **战斗统计（CombatStat）加星和锻造**：本回合获得的星、本回合 / 本场花掉的星、本场锻造总量。现在只有出牌数（按类型）、花掉的能量、受到的伤害、抽牌数、消耗数、生成的充能球数。这几项都能从别处推出来（君王之剑的伤害、银河尘埃的计数），不是必需。
8. 充能球相关的特征（全局特征 10、玩家统计 15–18、候选特征 8–9 的冰霜部分）对储君恒为 0，从零训练时不影响，保留即可。

## 四、观测以外要改的地方（故障机器人写死的）

- `python/sts2rl/curriculum.py`：起始牌组（储君：打击×4、防御×4、坠星 FallingStar、尊崇 Venerate）、卡池 `REGENT_CARD_POOL`、遗物池与药水池、默认角色。
- `python/sts2rl/actor.py`、`evaluator.py`、`solver_pool.py`、`rust_search.py`、`live_import.py`（直播导入的角色映射）、`config.py`（牌组大小上限用的是故障机器人 A10 赢局的人类数据，要换成储君的）：角色写死为 DEFECT。
- 引擎：`CombatSpec.Character` 默认 DEFECT；`ObsTables.cs`、`SimTables.cs` 用故障机器人的一局生成表，要确认表本身与角色无关（遍历 ModelDb 的部分没问题，取自这一局的部分要看）。`Program.cs` 已经列了五个角色。
- 星和锻造在 sts2-sim 里已有实现（`ForgeCmd.cs`、`SovereignBlade.cs`、储君遗物与药水），以后做搜索可以用，但储君上的一致性还没验收（第三幕双 Boss 的验收只覆盖了故障机器人）。Rust 引擎没有储君。

## 五、建议的做法

- 以上观测改动合成一个新格式版本（FormatVersion 20），按版本门控（AGENTS.md：字段是版本相关的），sts2-sim 的移植版编码器（ObsPort）同步。
- 从零训练用同样的架构，网络输入维度不变（新增的特征放进现有的空位或新的记录类型），故障机器人的检查点不受影响。
- 开训前先做两项核对：储君整局的观测与游戏界面逐项对照（尤其星费、君王之剑、牌堆顶）；sts2-sim 的储君对拍（为以后的搜索做准备，不阻塞训练）。
